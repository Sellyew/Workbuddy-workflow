我的 WorkBuddy 配置

Pedro H. C. Sant'Anna · Emory University · WorkBuddy 中文移植版（个人学习用）
持续开发与维护中。本文概述这套工作流如何用于学术工作——幻灯片、论文、数据分析等等。经济学、能源、政治学与工程学的研究团队都在采用它：2026 年 3 月的调查中有 15+ 个研究团队；此后仓库的 fork 数已超过 2,900、star 数超过 1,500（GitHub，2026-08-24）。fork 不等于研究团队——这两个数字衡量的是不同的东西。这些文件一直在被修订。

这是用 WorkBuddy 做 AI 辅助学术工作的一个基础框架。你描述自己想要什么——讲义幻灯片、一篇研究论文、一次数据分析、一个复现包——然后由 WorkBuddy 规划思路、运行专用代理、修复问题、核验质量并呈现结果：目标先行、门禁强制。就像一位包办整个工程的承包商，而你是审查者，负责裁定评审循环暴露出来的那些分歧。它刻意不是一个自主守护进程：每一次循环都由你或某个技能启动，绝不会自行启动。

它解决的问题

产出学术成果，已经不再是慢的那一环。检查才是。 AI 起草一讲稿、跑一个回归、写下描述结果的那一段，速度比你读完它们还快——而这些输出中的每一个，都可能自信而流畅地出错，错得看起来和正确一模一样。

有人在一个可运行的代码库里刻意埋了 20 个 bug，然后让评审代理再检查一遍。它们报告说一切正常。

输出里没有任何东西，能把这种情况和一次真正干净的运行区分开。

所以这个模板围绕一个想法构建：一项检查靠抓到东西赢得信任，而不是靠存在。它的每一个门禁都被喂过一个刻意埋入的缺陷，并确认会变红——召回率与误报率记在一份资质台账里，而这份台账本身就是门禁之一：一项检查若在其中没有行，构建就失败。那些尚未测量的部分在那里被逐一点名，作为可见的欠账，因为一项未经资质认定的检查不是弱证据——它根本不是证据。

从你所在的位置开始

如果你是…从这里开始
在写论文 /review-paper --peer aer 模拟一位编辑和两位带审稿取向的审稿人。/verify-claims 把每条引文、每个数字对回源头。/challenge 追问你的结果能否经受住那些你没跑过的设定。
在跑分析 /data-analysis 负责端到端的 R 流水线，某个数字错了而你不知为何时，用 /diagnose。
在教一门课 /syllabus → /create-lecture → /scaffold-exercises，Beamer 与 Quarto 保持同步，并由教学法、版式与校对代理审读。
在复现或在审稿 /audit-reproducibility 把论断对回输出；/differential-audit 比对两份实现；/replication-package 构建 AEA DCAS 存档。

这里的核验如何运作

7 级阶梯，每一级之所以存在，都是因为更便宜的一级放过了某个问题。第一级是大多数工作流会跳过的那一级：

  1. 给检查器做资质认定。植入失败，确认它变红，对着一个干净对照测量召回率与误报率。/vaccinate。
  2. 确定性门禁。凡是可判定的东西都该放进脚本，而不是代理的提示词——代理会漏掉脚本永不会漏的东西。一条命令：./scripts/backtest.sh。
  3. 产物核验。存在 → 实质 → 接线 → 自洽。只有最后一层能抓住「所有检查都通过，论文仍然是错的」。
  4. 独立性。看过稿子的审读者无法当作没看过，所以核验者在独立上下文里运行，从不接收它。
  5. 分析层面的核验。这个论断能否经受住那些你没做的选择？设定曲线，加上点名的敏感性统计量。
  6. 台账。试过的每一个设定（包括零结果）都记录在案，解释写在检验跑起来之前。
  7. 一位外部审稿人。最后是另一家厂商的前沿模型——这样它是确认，而不是发现。

有两件事本模板说得直白，因为它们是被测量出来的，而不是假定出来的：AI 同行评审不会降低分析选择上的方差（它能抓错误；稳健性是另一级），以及模型之间一致并不等于确证——它们会在同一个错误答案上彼此相关。

可信度的五个问题

AI 辅助的实证工作出错，最常见的方式不是某个数字算错，而是把一个问题的证据，读成了另一个问题的证据。

可复现性（代码跑得起来，并产出报告里的数字吗？）→ 实现保真度（它实现的是它声称的那个估计量吗？）→ 统计表现（它在有限样本里表现如何？）→ 测量效度（这个变量捕捉到了那个构念吗？）→ 识别策略（这个因果论断站得住吗？）。

一个问题的证据，从不清偿另一个问题。当一个代理报告「所有检查通过」时，它几乎总是在说第一个问题，而人们听成的是最后一个。

你会得到什么

本模板 19 个代理、63 个技能、37 条规则、11 个钩子——以及 11 个门禁，装好 pre-commit 钩子之后在每次提交前运行，并在 CI 里全量运行。

  • 63 个技能覆盖整个研究生命周期——论文、分析、模拟、复现包、申请书、幻灯片与教学。
  • 19 个专用代理——审稿人、校对者、版式审查者、代码审读者、一位独立上下文的论断核验者——每一个都钉在某个模型档位与算力档位上。
  • 37 条规则——多数按路径作用域，只在相关时加载，少数常开——外加 11 个会动手而不是唠叨的钩子，其中一个拒绝让某条 shell 命令悄悄改写门禁所定义在的那些设置与钩子文件。
  • 11 个门禁，一条命令。表面一致性、技能完整性、模型时效性、链接、规格符合性、陈旧度、仓库卫生、派生计数、台账覆盖率、一组带种子的钩子电池（把每个防线钩子对着它针对的失败再点一次火），以及一套可移植性回归集（路径、编码、行尾与 git 输出换一台机器后仍给出同一个答案；本机跑不到的用例会被点名并记成有上限的通过，而不是藏进 PASS）——跑过 ./scripts/install-hooks.sh 之后在每次提交前运行（钩子电池只在某个钩子、它的设置或电池本身被暂存时才跑），而全部门禁都在 CI 里跑。
  • 默认带审计轨迹——issue 作为缺陷记忆，进度报告作为工作记忆，外加一份资质台账，记录哪些检查真的被证明能检出东西。

诚实的适用范围

  • 结果仍然由你负责。本模板让检查更便宜，但不转移判断。识别策略、估计目标的选择、以及一个结果意味着什么，依然归你。
  • 它不是自主的。每一次评审循环都由你、或由你调用的某个技能启动。没有守护进程，而这是刻意的非目标。
  • 为经济学而建，也被用在经济学之外——核验层与领域无关；敏感性与期刊校准那两部分不是。
  • 它要花钱。模型路由把机械性工作留在便宜档位上，但一次完整的同行评审模拟并不免费。

开始使用

# Fork this repo on GitHub, then:
git clone https://github.com/YOUR_USERNAME/Workbuddy-workflow.git my-project
cd my-project
./scripts/install-hooks.sh    # activates the gate suite on every commit

启动 WorkBuddy，用两三句话描述你的项目，它会读配置，并把工作流调整到你的用途上。你不需要在第一天就用上全部东西——从 CODEBUDDY.md 和两三个技能开始，等你撞上它们所解决的问题时再逐个加上。
