我的 WorkBuddy 配置

Pedro H. C. Sant'Anna · Emory University · WorkBuddy 中文移植版（个人学习用）
持续开发与维护中。本文介绍这套工作流如何辅助完成幻灯片、论文和数据分析等学术任务。2026 年 3 月的调查记录了来自经济学、能源、政治学与工程学的 15+ 个研究团队；截至 2026-08-24，上游仓库已有 2,900 多次 fork 和 1,500 多个 star。一次 fork 不等于一个研究团队，这两个数字不能混为一谈。仓库文件仍在持续修订。

这个模板用 WorkBuddy 辅助学术研究。你可以让它制作讲义幻灯片、撰写研究论文、分析数据或组装复现包。WorkBuddy 会规划步骤、调用专用代理、修复问题并核验质量，你负责审查结果和裁决评审中的分歧。模板不会作为自主守护进程运行，每一轮循环都由你或你调用的技能启动。

它解决的问题

AI 已经能快速产出学术成果，检查反而成了瓶颈。 它起草讲稿、运行回归、撰写结果说明的速度，比你读完这些内容还快。每份输出都可能带有错误，却又写得自信流畅，让人难以分辨。

有人在一个可运行的代码库中刻意植入 20 个 bug，再让评审代理检查。代理却报告一切正常。

仅凭输出，你无法区分这次漏报和一次真正没有问题的运行。

因此，这个模板只信任经过实测的检查：检查必须证明自己能发现问题，不能因为存在就被视为有效。维护者向每个门禁植入过缺陷，并确认它会失败；召回率与误报率记录在资质台账中。台账本身也受门禁约束，已登记的检查若没有对应行，构建就会失败。尚未实测的检查会按名列出，因为未经有效性验证的检查不是弱证据，而是没有证据。

从你所在的位置开始

如果你是…从这里开始
在写论文 /review-paper --peer aer 模拟一位编辑和两位按审稿取向设定的审稿人。/verify-claims 把每条引文和每个数字追溯到源头。/challenge 检查结果能否经受住你尚未尝试的设定。
在跑分析 /data-analysis 运行完整的 R 分析流水线；如果某个数字有误且原因不明，使用 /diagnose 定位问题。
在教一门课 依次使用 /syllabus → /create-lecture → /scaffold-exercises，保持 Beamer 与 Quarto 同步，并让教学法、版式与校对代理分别审读。
在复现或在审稿 /audit-reproducibility 把论断与输出交叉核对；/differential-audit 比对两份实现；/replication-package 构建符合 AEA DCAS 的复现包。

这里的核验如何运作

核验分为 7 级阶梯。每增加一级，都是为了发现前一级漏掉的问题。第一级正是大多数工作流会跳过的步骤：

  1. 验证检查器。植入缺陷，确认检查会失败，再对照无缺陷样本测量召回率与误报率。使用 /vaccinate。
  2. 确定性门禁。凡是能明确判定的要求，都应写进脚本，而不是只写进代理提示词。代理可能漏检；脚本不会因注意力漂移漏跑已编码规则，但覆盖和实现仍需验证。运行一条命令即可：./scripts/backtest.sh。
  3. 产物核验。依次检查产物是否存在、是否有实质内容、各部分是否连接正确、整体是否自洽。只有最后一层能发现「所有检查都通过，但论文仍然有误」。
  4. 独立性。看过草稿的审读者不能当作没看过，因此核验者要在独立上下文中运行，且从不接收草稿。
  5. 分析层面的核验。检查论断能否经受住你尚未尝试的分析选择，包括设定曲线和明确指定的敏感性统计量。
  6. 台账。记录尝试过的每个设定，包括零结果，并在检验运行之前写好解释。
  7. 一位外部审稿人。最后调用另一家厂商的前沿模型，用于复核已有结果，而不是代替此前的发现过程。

以下两点来自实测，不是假定：另一项受控研究发现，AI 同行评审几乎未降低分析选择的离散度。它能发现错误，但稳健性需要另一级核验。模型之间一致也不等于确证，因为它们可能共同给出同一个错误答案。

可信度的五个问题

AI 辅助实证研究时，常见的错误不是算错某个数字，而是误把一个问题的证据当成另一个问题的答案。

可复现性：代码能运行并生成报告中的数字吗？→ 实现保真度：代码实现的是它声称的估计量吗？→ 统计表现：估计量在有限样本中表现如何？→ 测量效度：变量捕捉到了目标构念吗？→ 识别策略：因果论断站得住吗？

回答一个问题，并不等于回答另一个问题。当代理报告「所有检查通过」时，它通常只在回答第一个问题，读者却可能误以为最后一个问题也有了答案。

你会得到什么

本模板 19 个代理、63 个技能、37 条规则、11 个钩子，另有 12 个门禁。安装 pre-commit 钩子后，门禁会在每次提交前运行，并在 CI 中全量运行。

  • 63 个技能覆盖论文、分析、模拟、复现包、申请书、幻灯片与教学等研究工作。
  • 19 个代理包括 18 个科研/审读代理（审稿人、校对者、版式审查者、代码审读者、独立上下文的论断核验者等）和 1 个 Harness 自检代理 ping。18 个科研/审读代理均配置模型档位与 effort 思考预算；ping 未设置 effort。
  • 37 条规则多数按路径作用域加载，只在处理相关文件时生效，少数始终开启。11 个钩子会直接拦截或执行操作，其中一个会拒绝 shell 命令悄悄改写定义门禁的设置与钩子文件。
  • 12 个门禁，一条命令。检查范围包括表面一致性、技能完整性、模型时效性、链接、规格符合性、陈旧度、仓库卫生、派生计数、台账覆盖率、钩子测试、可移植性和幻灯片内容不变量。带固定种子的钩子测试组会让每个防线钩子重新面对它要拦截的失败。可移植性回归集检查路径、编码、行尾与 git 输出在换机器后是否仍给出相同答案；本机无法运行的用例会明确列出，并记为有上限的通过，不会藏进 PASS。幻灯片内容不变量检查包括引文键能否在唯一的文献库中解析，以及每页彩色框是否超过两个；此前，这两条只有文字要求。运行 ./scripts/install-hooks.sh 后，门禁会在每次提交前执行。只有暂存内容包含某个钩子、对应设置或测试组本身时，才运行钩子测试组；CI 则运行全部门禁。
  • 默认保留审计轨迹：issue 记录缺陷，进度报告记录工作过程，资质台账记录哪些检查已经证明能够发现问题。

诚实的适用范围

  • 结果仍然由你负责。模板降低了检查成本，但不会替你判断。识别策略、估计目标的选择和结果解释仍由你决定。
  • 它不会自主运行。每轮评审都由你或你调用的技能启动。模板刻意不提供守护进程。
  • 它为经济学设计，也可用于其他领域。核验层与领域无关，但敏感性分析与期刊校准并非如此。
  • 使用它需要承担模型费用。模型路由会把机械性工作分配给低成本档位，但完整的同行评审模拟仍会产生费用。

开始使用

# Fork this repo on GitHub, then:
git clone https://github.com/YOUR_USERNAME/Workbuddy-workflow.git my-project
cd my-project
./scripts/install-hooks.sh    # activates the gate suite on every commit

启动 WorkBuddy，新建任务，将 my-project 选为工作空间根目录，再粘贴起始提示词，用两三句话描述项目。它会读取配置，并根据你的用途调整工作流。你不必一开始就使用全部功能，可以先从 CODEBUDDY.md 和两三个技能入手，遇到相应问题时再逐个采用。
