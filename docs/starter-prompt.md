# 中文 Starter Prompt

把下面整段复制到 WorkBuddy 的**新会话**里。它做的事：让代理先读项目契约、按计划模式开工、并且**不许**把「文件已存在」当成「功能已跑通」。

适用场景：你刚 fork 了这个模板，或者开了一个新项目、新论文、新讲次。

---

## 一、首次使用（初始化）

```
我要把这个模板初始化成我的科研项目。请先读 CODEBUDDY.md 和 UPSTREAM.md，
然后执行 /init-research-project。

我的项目信息：
- 项目名称：（例：劳动经济学讲义 / 某篇论文的暂定名）
- 单位与作者：
- 学科：（例：应用微观经济学）
- 主要交付物：（讲义 / 论文 / 两者）
- 目标期刊或会议：
- 数据是否有访问限制：（有 → 说明限制；没有 → 写「无」）
- 用 Stata / R / Python 中的哪些：
- 写作语言：（中文 / 英文）

按你的技能定义走阶段 0→4。任何一项门禁没全绿，不要往下走，把红的原样贴给我。
不要替我猜任何一项——拿不准就问我，一次把问题问全。
```

## 二、日常开工（已经初始化过）

```
先读 CODEBUDDY.md 的「核心原则」与「范围纪律」两节，再动手。

任务：<一句话说清要做什么>

要求：
1. 先勘察，后计划。读相关文件之后给我一个计划（改哪些文件、每处改什么、
   怎么验证），我批准了再执行。
2. 范围纪律：只做我要求的事。你发现别的问题，列在最后当建议，不要顺手改。
3. 改完必须验证：
   - 改了 .tex → 实际编译，确认 PDF 生成且页数合理；
   - 改了 .qmd → 实际渲染，确认 HTML 生成；
   - 改了 .R / .py → 实际跑，确认输出文件生成且数字对得上；
   - 改了规则/技能/代理 → 跑 python scripts/backtest.py，全绿才算完。
4. 报告格式：做了什么 → 验证证据（命令 + 输出关键行）→ 没做什么 → 建议。
   不要用「已完成」「已优化」这种没有证据的词。
```

## 三、审读一篇稿子

```
用 /review-paper --peer 审这篇：<路径>

目标期刊：<刊名>（决定审稿人的校准）
我的顾虑：<例如「识别策略站不站得住」「文献定位是否过时」>

要求：
- 审稿人独立上下文，不要把我这段话带进去当提示；
- 每条发现必须能指到具体行，说清违反了哪条规则、什么情况下会出错；
- 不要替我改稿子，先给我发现清单，我自己决定改哪些。
```

## 四、讲一讲这节课怎么做

```
用 /create-lecture 做第 <N> 讲：<主题>

学生背景：<先修课 / 已掌握什么>
时长：<分钟>
必须覆盖：<知识点清单>
不要覆盖：<明确排除的内容，避免讲太满>

要求：
- Beamer .tex 为权威源，Quarto 由它派生；
- 不要用 \pause / \onslide 等 overlay 命令（见 .codebuddy/rules/no-pause-beamer.md）；
- 做完跑一遍 /slide-excellence，把 CRITICAL 修掉再给我。
```

## 五、卡住了 / 数字对不上

```
诊断模式：<现象>

已知：
- 我跑了什么命令：
- 期望看到什么：
- 实际看到什么（原样贴输出，不要概括）：
- 最近改过什么：

要求：按 /diagnose 的流程走。先复现，再二分定位，再说根因。
在你确认真实根因之前，不要给我「可能的原因」清单。
```

---

## 用法要点（给人看的，不用复制）

1. **第一段永远先让它读 `CODEBUDDY.md`。** 那份文件每次会话都会被加载，但让代理**显式**读一遍，它才会真的把「范围纪律」和「验证义务」当约束而不是背景。
2. **「验证证据」这句话要常驻。** 这个模板最大的失败模式不是写错代码，而是**声称做完了**。要求它贴命令与输出关键行，是唯一便宜的对抗手段。
3. **不要一次给三件事。** 一次一个任务，计划会短、验证会具体、回滚会干净。
4. **中英混排的项目**：告诉它「术语首次出现写中文（English），其后只用中文」，否则它会在同一段里来回切。
5. 想换风格（更啰嗦 / 更简洁 / 更像审稿人），改 `.codebuddy/output-styles/` 里的文件，或者在会话里直接说「用 referee 风格回答」。
