# 中文起始提示词

把下面整段复制到 WorkBuddy 的**新会话**里。提示词会要求代理先读项目约定，再进入计划模式，并且**不得**把「文件已存在」当成「功能已跑通」。

适用于刚 fork 模板，或开始新项目、新论文、新讲次的情况。

---

## 一、首次使用（初始化）

```
我要把这个模板初始化成我的科研项目。请先读 CODEBUDDY.md，
然后执行 /init-research-project。

我的项目信息：
- 项目名称：（例：劳动经济学讲义 / 某篇论文的暂定名）
- 单位与作者：
- 学科：（例：应用微观经济学）
- 主要交付物：（讲义 / 论文 / 两者）
- 目标期刊或会议：
- 数据是否有访问限制：（有 → 说明限制；没有 → 写「无」）
- 用 Stata / R / Python 中的哪些：
- 写作语言：（中文 / 英文）

按你的技能定义走阶段 0→4。出现 FAIL 或非零退出才停止，把失败输出原样贴给我。
PARTIAL/SKIPPED 要原样报告检查范围和原因，不能冒充完整通过。
不要替我猜任何一项——拿不准就问我，一次把问题问全。
```

## 二、日常开工（已经初始化过）

```
先读 CODEBUDDY.md 的「核心原则」与「范围纪律」两节，再动手。

任务：<一句话说清要做什么>

要求：
1. 先勘察，后计划。读相关文件之后给我一个计划（改哪些文件、每处改什么、
   怎么验证），我批准了再执行。
2. 范围纪律：只做我要求的事。你发现别的问题，列在最后当建议，不要顺手改。
3. 改完必须验证：
   - 改了 .tex → 实际编译，确认 PDF 生成且页数合理；
   - 改了 .qmd → 实际渲染，确认 HTML 生成；
   - 改了 .R / .py → 实际跑，确认预期输出已生成；涉及数值时，再与预期值或基准输出核对；
   - 改了规则/技能/代理 → 跑 python scripts/backtest.py；出现 FAIL 或非零退出才停止。
     PARTIAL/SKIPPED 要原样报告检查范围和原因，不能冒充完整通过。
4. 报告格式：做了什么 → 验证证据（命令 + 输出关键行）→ 没做什么 → 建议。
   不要在缺少证据时使用『已完成』『已优化』等表述。
```

## 三、审读一篇稿子

```
用 /review-paper --peer 审这篇：<路径>

目标期刊：<刊名>（决定审稿人的校准）
我的顾虑：<例如「识别策略站不站得住」「文献定位是否过时」>

要求：
- 审稿人独立上下文，不要把我这段话带进去当提示；
- 每条发现必须能指到具体行，说清违反了哪条规则、什么情况下会出错；
- 不要替我改稿子，先给我发现清单，我自己决定改哪些。
```

## 四、讲一讲这节课怎么做

```
用 /create-lecture 做第 <N> 讲：<主题>

学生背景：<先修课 / 已掌握什么>
时长：<分钟>
必须覆盖：<知识点清单>
不要覆盖：<明确排除的内容，避免讲太满>

要求：
- Beamer .tex 为权威源，Quarto 由它派生；
- 不要用 \pause / \onslide 等 overlay 命令（见 .codebuddy/rules/no-pause-beamer.md）；
- 做完跑一遍 /slide-excellence，把 CRITICAL 修掉再给我。
```

## 五、卡住了 / 数字对不上

```
诊断模式：<现象>

已知：
- 我跑了什么命令：
- 期望看到什么：
- 实际看到什么（原样贴输出，不要概括）：
- 最近改过什么：

要求：按 /diagnose 的流程走。先复现并最小化，再列出、排序和验证候选假设。
根因及其作用机制未确认前，不要修复。
```

## 用法要点（给人看的，不用复制）

1. **第一段始终要求代理阅读 `CODEBUDDY.md`。** 虽然这份文件会在每次会话中加载，但让代理**显式**再读一遍，可以促使它把「范围纪律」和「验证义务」当作必须遵守的约束，而不是背景信息。
2. **始终要求提供「验证证据」。** 这个模板最需要防止的不是代码写错，而是代理**声称已经完成**。要求它贴出命令和输出关键行，是成本最低的直接检查手段。
3. **不要一次交代三件事。** 每次只给一个任务，计划会更短，验证会更具体，回滚也更容易。
4. **中英混排的项目**：告诉代理「术语首次出现写中文（English），其后只用中文」，避免同一段落反复切换译名。
5. 如果想调整风格，例如更详细、更简洁或更像审稿人，可以修改 `.codebuddy/output-styles/` 里的文件，也可以在会话中直接说「用 referee 风格回答」。
