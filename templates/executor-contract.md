## 这项工作必须通过的门禁

```bash
[./scripts/backtest.sh]          # or the standing gate for the surface being touched
```

这里的**完成**是指门禁已经实际运行并通过。提交和推送是行为授权，不是位置授权：门禁实际运行并通过后，只有另获提交授权才可提交，只有另获推送授权才可推送；按 verified → committed → pushed 的实际到达状态依次报告。未获相应授权时，带着证据和通过的门禁结果交回。不得提前宣称完成（法则 19）。应当主动运行门禁，不能等 pre-commit 钩子来发现问题。

提交本身也受门禁约束。如果本仓库要求明确签核才能提交（[`/commit`](../.codebuddy/skills/commit/SKILL.md)），受委派执行者的*完成*就只表示**门禁通过并带着证据交回**。提交是另一个需要授权的步骤，执行者绝不能为了满足上述要求而自行提交。

## 填好的示例（虚构）

**目标。** 每日摄取流程为登记表中的每个站点生成每天一行的数据，下游使用方能够区分「当天没有观测」与「从未执行摄取的日期」。

**验收门槛。**

- [ ] `python3 pipeline/audit_coverage.py --since 2020-01-01` 以 0 退出，并写出 `outputs/coverage_audit.csv`；审计输出的最后一行报 `missing_days: 0`。
- [ ] 在改动前的 commit 上运行同一条命令，会报出非零的 `missing_days`。信任通过结果之前，先证明这个检查器能够发现缺失。

**自有路径。** `pipeline/ingest.py`（编辑）、`pipeline/audit_coverage.py`（创建）、`tests/test_coverage.py`（创建）。

**门禁。** `pytest tests/ -q` 与仓库的常设检查器套件，报告之前两者都必须通过。

**输出契约。** 结构化返回，含 `files_changed`、`evidence`（逐字记录上述两条命令及其最后的摘要行）、`open_issues`；`outputs/coverage_audit.csv` 存进运行目录。

**机制（可否决）。** *假设 A：*与一张生成的日历表做左连接，是明确标出缺失的最简便办法。*假设 B：*在摄取时写一行哨兵。如果加载器已经写出显式的无观测标记，两个假设都不需要采用；说明这一点，然后停止。

**不要碰什么。** 给下游使用方的已发布 schema、留存政策，以及 `outputs/` 下除新审计 CSV 之外的任何文件。
