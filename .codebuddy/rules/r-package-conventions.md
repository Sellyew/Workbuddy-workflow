# R 包开发标准

**标准：** 一个 CRAN 就绪的包。`R CMD check --as-cran` 返回 0 个 error、0 个 warning，只有已解释的 note。

> **范围：** 本条规则覆盖 R **包源码**（`R/`、`tests/`、`DESCRIPTION`、`NAMESPACE`、`man/`、vignette）。一次性的**分析脚本**、模拟和图形代码见 [`r-code-conventions.md`](r-code-conventions.md) —— 那边规则不同（顶层 `set.seed()`、`library()` 放在顶部、相对输出路径）。包正好相反：`R/` 里没有 `library()`、具名空间导入、生成的文档。

---

## 1. 包的结构

```
pkg/
├── DESCRIPTION        # metadata + dependencies (hand-edited)
├── NAMESPACE          # GENERATED by roxygen — never hand-edit
├── R/                 # package code
├── man/               # GENERATED .Rd by roxygen — never hand-edit
├── tests/testthat/    # testthat tests
├── vignettes/         # long-form docs
└── NEWS.md            # user-facing changelog
```

**`man/` 和 `NAMESPACE` 是生成的。** 改 `R/` 里的 roxygen 块并运行 `devtools::document()` —— 绝不手改 `.Rd` 文件或 `NAMESPACE`。一份手改过的 `NAMESPACE` 一旦与 roxygen 块不一致，就是一次迟早要发生的 check 失败。

## 2. 依赖与 DESCRIPTION

- **`Imports`** 用于 `R/` 代码里用到的包。**`Suggests`** 用于只在测试、vignette 或可选代码路径里用到的包（用 `requireNamespace(..., quietly = TRUE)` 兜住）。**`Depends`** 只在用户确实需要该依赖被附加时使用（罕见 —— 优先 `Imports`）。
- **绝不在 `R/` 里用 `library()` / `require()`。** 依赖通过 `pkg::fun()` 引用，或用 roxygen `@importFrom pkg fun` 导入。包代码里的 `library()` 是一个 check NOTE，并且污染用户的搜索路径。
- 只在依赖某个版本引入的特性时，才加**版本下限**（`dplyr (>= 1.1.0)`）。
- **`Authors@R`** 带角色（`aut`、`cre`；适用时加 `cph`/`fnd`）、一个真实的 `License`（需要时加 `LICENSE` 文件），以及一段 `Description`，开头不要用 "This package…" / "A package…"（那是一个 check NOTE）。

## 3. 文档（roxygen2）

- **每个导出函数**都要记录**全部**参数（`@param`）、返回值（`@return`），并有一个**可运行**的 `@examples` 块。把慢的／联网的／交互式的示例包进 `\donttest{}` 或 `@examplesIf`；绝不用 `\dontrun{}` 去藏一个确实会报错的示例。
- `@export` 决定什么进入 `NAMESPACE`。内部辅助函数保持不导出（可选加 `@keywords internal`）。
- 为数据集写文档（`@format`、`@source`），并加一个包级文档页（`"_PACKAGE"`）。

## 4. 测试（testthat，第 3 版）

- 测试放在 `tests/testthat/`；设定第 3 版（`Config/testthat/edition: 3`）。用 `expect_*()` —— 每个导出函数至少有一个测试覆盖其契约以及边界情形（空输入、`NA`、边界值）。
- **不泄漏全局状态：** 用 `withr::*` 或 `on.exit()` 恢复 `options()`、`par()`、工作目录、环境变量和 RNG 状态。一个改了全局状态却不恢复的测试，会弄坏无关的测试。
- 慢的或依赖网络的测试用 `skip_on_cran()` / `skip_if_offline()`。信息量大的打印输出用 `expect_snapshot()`。

## 5. CRAN 就绪的红旗

| 红旗 | 为什么过不了 | 改为 |
|---|---|---|
| `R/` 里的 `library()` / `require()` | NOTE；污染搜索路径 | `@importFrom` 或 `pkg::fun()` |
| 写到 `tempdir()` 之外 | 违反政策（写进用户 library/home） | 只写 `tempdir()`；返回路径 |
| `<<-` 赋给全局环境 | 违反政策 | 返回值；有意识地使用环境 |
| 函数里的 `print()` / `cat()` | 输出不可控 | `message()` / `warning()`；用 `verbose` 控制 |
| `options()` / `par()` 改了没恢复 | 副作用 | `on.exit(...)` 或 `withr::with_*` |
| 用 `T` / `F` 而不是 `TRUE` / `FALSE` | 可被重新赋值 | 总是 `TRUE` / `FALSE` |
| 会报错或跑很久的示例 | 报错则 ERROR；慢则 timing NOTE | 修好；慢但正确的包进 `\donttest{}` |
| `\dontrun{}` 掩盖失败 | 遮住坏掉的示例 | `\donttest{}` 只用于慢但正确的 |
| 未声明的选项参数 | 静默的笔误 | `match.arg(method)` |

## 6. 版本与 NEWS

- 每次改动都在 `DESCRIPTION` 里升 `Version`（开发版用第 4 段，例如 `1.2.0.9000`）。遵循类语义化版本：破坏 API 的改动升 major。
- 每个面向用户的改动都在目标版本下有一条 `NEWS.md` 条目。优雅地弃用（`lifecycle::deprecate_warn()`），不要在没有弃用周期的情况下移除导出函数。

## 7. 发布门禁

在任何发布或 CRAN 投稿之前，运行 [`/r-package-check`](../skills/r-package-check/SKILL.md)：它会跑 `devtools::document()`、`devtools::test()` 和 `R CMD check --as-cran`，然后按 CRAN 政策逐条分诊每个 ERROR / WARNING / NOTE。**0 error、0 warning，且每个残留 note 都有一份书面理由**，这是门槛。

## 8. 清单

```
[ ] NAMESPACE + man/ regenerated via devtools::document() (not hand-edited)
[ ] No library()/require() in R/; deps via @importFrom or pkg::fun()
[ ] Imports/Suggests/Depends classified correctly; Authors@R + License set
[ ] Every exported fn: @param (all args) + @return + runnable @examples
[ ] testthat 3e; exported fns tested; global state restored (withr/on.exit)
[ ] No <<-, no writes outside tempdir(), no T/F, no print()/cat() in functions
[ ] Version bumped + NEWS.md entry
[ ] R CMD check --as-cran: 0 errors, 0 warnings, notes explained
```
