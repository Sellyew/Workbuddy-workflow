# R 包开发标准

**标准：**包必须达到 CRAN 就绪状态。`R CMD check --as-cran` 返回 0 个 error、0 个 warning，只允许保留已解释的 note。

> **范围：**本规则覆盖 R **包源码**，包括 `R/`、`tests/`、`DESCRIPTION`、`NAMESPACE`、`man/`、vignette。一次性的**分析脚本**、模拟和图形代码见 [`r-code-conventions.md`](r-code-conventions.md)，两者规则不同：分析脚本要求顶层 `set.seed()`、`library()` 放在顶部、使用相对输出路径；包则正好相反，`R/` 中没有 `library()`，使用具名空间导入和生成的文档。

---

## 1. 包的结构

```
pkg/
├── DESCRIPTION        # metadata + dependencies (hand-edited)
├── NAMESPACE          # GENERATED by roxygen — never hand-edit
├── R/                 # package code
├── man/               # GENERATED .Rd by roxygen — never hand-edit
├── tests/testthat/    # testthat tests
├── vignettes/         # long-form docs
└── NEWS.md            # user-facing changelog
```

**`man/` 和 `NAMESPACE` 都是生成物。**修改 `R/` 中的 roxygen 块后，运行 `devtools::document()` 重新生成，绝不能手改 `.Rd` 文件或 `NAMESPACE`。手改的 `NAMESPACE` 一旦与 roxygen 块不一致，check 迟早会失败。

## 2. 依赖与 DESCRIPTION

- **`Imports`** 用于 `R/` 代码使用的包。**`Suggests`** 用于只在测试、vignette 或可选代码路径中使用的包，并用 `requireNamespace(..., quietly = TRUE)` 兜住。**`Depends`** 只用于用户确实需要附加该依赖的情况；这种情况罕见，应优先使用 `Imports`。
- **绝不在 `R/` 中使用 `library()` / `require()`。**通过 `pkg::fun()` 引用依赖，或用 roxygen `@importFrom pkg fun` 导入。包代码中的 `library()` 会产生 check NOTE，还会污染用户的搜索路径。
- 只有依赖某个版本引入的特性时，才添加**版本下限**，例如 `dplyr (>= 1.1.0)`。
- **`Authors@R`** 必须包含角色（`aut`、`cre`；适用时加 `cph`/`fnd`）、真实的 `License`（需要时添加 `LICENSE` 文件）和一段 `Description`。该段开头不要使用 "This package…" / "A package…"，否则会产生 check NOTE。

## 3. 文档（roxygen2）

- **每个导出函数**都必须记录**全部**参数（`@param`）和返回值（`@return`），并提供**可运行**的 `@examples` 块。慢、联网或交互式示例要包进 `\donttest{}` 或 `@examplesIf`；绝不能用 `\dontrun{}` 隐藏确实会报错的示例。
- `@export` 决定哪些内容进入 `NAMESPACE`。内部辅助函数保持不导出，也可选择添加 `@keywords internal`。
- 为数据集编写文档（`@format`、`@source`），并添加包级文档页（`"_PACKAGE"`）。

## 4. 测试（testthat，第 3 版）

- 测试放在 `tests/testthat/`，并通过 `Config/testthat/edition: 3` 设定第 3 版。使用 `expect_*()`；每个导出函数至少有一个测试覆盖其契约和边界情形，包括空输入、`NA`、边界值。
- **不泄漏全局状态：**用 `withr::*` 或 `on.exit()` 恢复 `options()`、`par()`、工作目录、环境变量和 RNG 状态。测试如果改变全局状态却不恢复，就会破坏无关测试。
- 慢或依赖网络的测试使用 `skip_on_cran()` / `skip_if_offline()`。信息量大的打印输出使用 `expect_snapshot()`。

## 5. 影响 CRAN 就绪的警示项

| 红旗 | 为什么过不了 | 改为 |
|---|---|---|
| `R/` 里的 `library()` / `require()` | NOTE；污染搜索路径 | `@importFrom` 或 `pkg::fun()` |
| 写到 `tempdir()` 之外 | 违反政策，会写进用户 library/home | 只写 `tempdir()`；返回路径 |
| `<<-` 赋给全局环境 | 违反政策 | 返回值；有意识地使用环境 |
| 函数里的 `print()` / `cat()` | 输出不可控 | `message()` / `warning()`；用 `verbose` 控制 |
| `options()` / `par()` 改了没恢复 | 产生副作用 | `on.exit(...)` 或 `withr::with_*` |
| 用 `T` / `F` 而不是 `TRUE` / `FALSE` | 可被重新赋值 | 总是 `TRUE` / `FALSE` |
| 会报错或跑很久的示例 | 报错会产生 ERROR，太慢会产生 timing NOTE | 修好；慢但正确的示例包进 `\donttest{}` |
| `\dontrun{}` 掩盖失败 | 隐藏坏掉的示例 | `\donttest{}` 只用于慢但正确的示例 |
| 未声明的选项参数 | 静默的笔误 | `match.arg(method)` |

## 6. 版本与 NEWS

- 每次改动都在 `DESCRIPTION` 中提升 `Version`，开发版使用第 4 段，例如 `1.2.0.9000`。采用类语义化版本：破坏 API 的改动提升 major。
- 每个面向用户的改动都要在目标版本下添加一条 `NEWS.md` 条目。使用 `lifecycle::deprecate_warn()` 优雅地弃用，不得在没有弃用周期的情况下移除导出函数。

## 7. 发布门禁

任何发布或 CRAN 投稿之前，运行 [`/r-package-check`](../skills/r-package-check/SKILL.md)。它会运行 `devtools::document()`、`devtools::test()` 和 `R CMD check --as-cran`，再按 CRAN 政策逐条分诊每个 ERROR / WARNING / NOTE。发布门槛是 **0 error、0 warning，且每个残留 note 都有书面理由**。

## 8. 清单

```
[ ] NAMESPACE + man/ regenerated via devtools::document() (not hand-edited)
[ ] No library()/require() in R/; deps via @importFrom or pkg::fun()
[ ] Imports/Suggests/Depends classified correctly; Authors@R + License set
[ ] Every exported fn: @param (all args) + @return + runnable @examples
[ ] testthat 3e; exported fns tested; global state restored (withr/on.exit)
[ ] No <<-, no writes outside tempdir(), no T/F, no print()/cat() in functions
[ ] Version bumped + NEWS.md entry
[ ] R CMD check --as-cran: 0 errors, 0 warnings, notes explained
```
