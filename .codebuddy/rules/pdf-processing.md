# 稳健的 PDF 处理

**默认：直接读 PDF。** Read 工具原生读取 PDF——论文超过约 10 页时传一个 `pages` 范围（例如 `pages: "1-20"`），每次请求最多 20 页——而 1M token 的上下文窗口能宽裕地装下一篇完整论文。你**不需要**把一篇普通论文预先切成片段文件。

## 工作流

**Step 1：先查大小**
```bash
pdfinfo paper_name.pdf | grep "Pages:"
ls -lh paper_name.pdf
```

**Step 2：直接读**
- **普通论文（最多约 100 页）：** 用 Read 工具读，用 `pages` 参数翻页（每次请求最多 20 页）。无需预切分。
- **有选择的深读（这是成本优化，不是容量上限）：** 对长论文，你可以逐节扫读，细读承重的部分（识别策略、方法、结果），略读附录／参考文献——这是省 token，不是因为模型装不下这份文档。

**Step 3（兜底）：只有在直接读取失败时才切分。** 仅当 PDF 确实超大（一本书或高分辨率扫描件、数百页）、已损坏，或直接 Read 报错时，才用 Ghostscript 按页范围切分：
```bash
mkdir -p paper_name/
for i in {0..9}; do
  start=$((i*5 + 1)); end=$(((i+1)*5))
  gs -sDEVICE=pdfwrite -dNOPAUSE -dBATCH -dSAFER \
     -dFirstPage=$start -dLastPage=$end \
     -sOutputFile="paper_name/paper_name_p$(printf '%03d' $start)-$(printf '%03d' $end).pdf" \
     paper_name.pdf 2>/dev/null
done
```
然后一份一份读这些页范围文件，逐步把理解搭起来。

## 错误处理协议

**如果直接读取失败**（损坏或超大）：退回 Step 3 的按页范围切分。

**如果某个片段处理失败：**
1. 记录有问题的片段（例如「Chunk p021-025 failed」）
2. 试着再切成 1-2 页的小块
3. 如果仍然失败，跳过并记录这个缺口

**如果切分失败：**
1. 检查 Ghostscript 是否已安装：`gs --version`
2. 试替代方案：`pdftk paper.pdf burst output paper_%03d.pdf`
3. 若全都不成，请用户手动上传指定的页范围

## 多份文档与一份文档是两个不同的问题

上面的指引针对的是**一份**论文：直接读它、翻页读它，上下文窗口能宽裕地装下。

**它不能靠乘法扩展。** 一次加载约 10 份大 PDF，已经反复导致 `Prompt is too long` 并被迫重置会话——而且是在部分工作已经做完、已经丢掉之后。

对任何跨**超过两三份文档**的任务——在一个语料库上做风格画像、在一整包里分诊审稿人的意见、一次文献扫读——用**每份文档一个子代理**的模式：

1. **每份文档生成一个子代理**，各自在独立上下文中。
2. 每个代理**只读自己那一份文件**，往磁盘写一条简短的结构化笔记（`notes/<name>.md`）——300 字，固定 schema。
3. 每个只回**文件名**，不回内容。
4. 主会话随后**只读这些笔记**并做综合。

主上下文里永远不会同时装着超过一份文档的材料，而一次失败只损失一个代理，不损失整个会话。

> **开工前先数数。** 如果任务点到的文档数量超过你两三次请求能读完的量，答案就是子代理——在开工前定下，而不是在第一次溢出之后。并且对着磁盘确认语料规模：一个说「我的论文」、结果查出十一份的任务，跟四份的任务是两个任务。
