# 质量审查与评分细则

> **框定：** 阈值在**框架层面是建议性的**。`/commit` 技能会跑 `quality_score.py`，失败就停下，直到用户修好或明确覆盖。一个**真正的 git pre-commit 钩子**（`.githooks/pre-commit`，通过 `./scripts/install-hooks.sh` 一次性激活）把同一套门禁扩展到*每一次*提交，所以绕过技能不再等于绕过审查——除非你用 `SKIP_QUALITY_GATE=1` / `--no-verify` 主动退出。这里的「门禁」指「由技能或 pre-commit 钩子强制执行的检查点」，不是无条件的框架级阻断。

## 阈值

- **80/100 = 可提交** -- 好到可以存下来
- **90/100 = 可提 PR** -- 可以部署
- **95/100 = 卓越** -- 值得追求

## 评分细则

`scripts/quality_score.py` 是这些扣分的单一真源：下面这些表格就是它的 `--print-rubric` 输出，若两者漂移，`check-derived-counts.py` 会让门禁总检失败。改脚本里的权重，然后重新生成。由**脚本**抓的行自动扣分；由**审稿人**抓的行没有检测器：脚本永不扣它们，它们是审稿人（`/slide-excellence`、`/review-r`、`/proofread`）按所列权重执行的清单。

## 执行（`/commit` 技能 + 可选的 pre-commit 钩子）

- **分数 < 80：** 在 `/commit` 内停止。列出阻断问题。用户可以用一句明确的自然语言信号（"commit anyway" / "skip quality gate"）加理由来覆盖——覆盖会记入提交正文。
- **分数 < 90：** 允许在 `/commit` 内提交，给出警告。列出建议。
- **直接 `git commit`：** 在你运行 `./scripts/install-hooks.sh` *之前*不受强制，该脚本把 `core.hooksPath` 指向版本控制的 `.githooks/pre-commit`。此后每一次提交（无论是否经由技能）都会跑门禁总检套件（只有当某个钩子、它的设置或钩子组本身被暂存时才跑钩子组；CI 永远跑全部）加上质量（≥80）门禁。尽量少用 `SKIP_QUALITY_GATE=1`（仅质量）或 `git commit --no-verify`（全部钩子）绕过；在提交正文里记下理由。
