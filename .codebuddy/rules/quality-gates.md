# 质量审查与评分细则

> **框定：**这些阈值在**框架层面是建议性的**。`/commit` 技能会运行 `quality_score.py`，失败后停下，直到用户修复问题或明确覆盖。一个**真正的 git pre-commit 钩子**（`.githooks/pre-commit`，通过 `./scripts/install-hooks.sh` 一次性激活）把同一套门禁扩展到*每一次*提交，因此绕过技能不再等于绕过审查，除非主动使用 `SKIP_QUALITY_GATE=1` / `--no-verify` 退出。这里的「门禁」是由技能或 pre-commit 钩子强制执行的检查点，不是无条件的框架级阻断。

## 阈值

- **80/100 = 可提交**：好到可以存下来。
- **90/100 = 可提 PR**：可以部署。
- **95/100 = 卓越**：值得追求。

## 评分细则

`scripts/quality_score.py` 是这些扣分的单一真源。下面的表格就是它的 `--print-rubric` 输出；两者一旦漂移，`check-derived-counts.py` 就会让门禁总检失败。修改脚本中的权重后，必须重新生成表格。由**脚本**发现的行会自动扣分；由**审稿人**发现的行没有检测器，脚本永远不会扣这些分，审稿人需按所列权重执行清单，使用 `/slide-excellence`、`/review-r`、`/proofread`。

## 执行（`/commit` 技能 + 可选的 pre-commit 钩子）

- **分数 < 80：**在 `/commit` 内停止，并列出阻断问题。用户可以用一句明确的自然语言信号加理由来覆盖，例如 "commit anyway" / "skip quality gate"；覆盖会记入提交正文。
- **分数 < 90：**允许在 `/commit` 内提交，但必须给出警告并列出建议。
- **直接 `git commit`：**运行 `./scripts/install-hooks.sh` *之前*不受强制。该脚本把 `core.hooksPath` 指向版本控制的 `.githooks/pre-commit`；此后每次提交，无论是否经由技能，都会运行门禁总检套件和质量（≥80）门禁。只有某个钩子、它的设置或钩子组本身被暂存时，才运行钩子组；CI 永远运行全部。尽量少用 `SKIP_QUALITY_GATE=1`（仅质量）或 `git commit --no-verify`（全部钩子）绕过，并在提交正文中记下理由。

## 质量报告

**只在合并时**生成，格式使用 `templates/quality-report.md`，保存到 `quality_reports/merges/YYYY-MM-DD_[branch-name].md`。
