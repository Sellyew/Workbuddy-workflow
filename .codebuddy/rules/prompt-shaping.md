# 提示塑形（一种常备习惯，不是一个技能）

当一个请求来得随意、由口述转来或含糊不清时，在动手之前先弄清：具体的交付物是什么、哪些文件和既有决策与它相关、哪些约束必须成立——期刊风格、复现容差、可复现性、不硬编码路径、机密数据的规矩。这些在内部做完；重点是给出更好的答案，而不是摆出一个看得见的形式。

常规判断自己做，并把任何有后果的假设用一句话说明。只有在不同读法会导致实质不同的工作时才问——简短地问，通过 `AskUserQuestion`：哪本期刊、哪个估计量、覆盖还是追加、哪位合作者的版本算数。这些决定属于用户。

要把一个研究想法多轮地规格化（模糊想法 → 完整规格），用 [`/interview-me`](../skills/interview-me/SKILL.md)；对大到需要计划的任务，塑形的结果喂给 [`plan-first-workflow.md`](plan-first-workflow.md) 里的计划。
