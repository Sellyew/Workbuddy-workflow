# 摘要与正文一致（反打地鼠）

**编辑任何摘要段落时，不要做外科手术式的词级修补。** 摘要与正文的漂移，发生在正文改了而摘要没有重新核对的时候。针对被点名的那句话做外科式修改，几乎总会在同一段的其他地方引入新的漂移。

## 什么算「摘要段落」

- CHANGELOG 中某个版本条目的开篇段落（第一个 `###` 子标题之前的导语）
- README.md 的标语与各节导语
- PR 标题与 `## Summary` 块
- 技能 / 规则 / 代理 frontmatter 的 `description:` 字段
- 指南 `workflow-guide.qmd` 的各节摘要
- MEMORY.md `[LEARN:*]` 条目的标题行（正文之前那句单句总结）
- 任何形如「本次发布做了 X。它没做 Y。计数是 Z。」的段落——三段式断言正是漂移磁铁

## 流程

当你编辑一个摘要段落时（或当某位审阅者——人、Copilot 或 Codex——点名了它）：

1. **读完整的正文**，即被总结的那部分。不只是 diff。全部。
2. **枚举当前摘要里的每一条实质断言**：每个名词清单（「技能、规则、钩子」）、每个数字、每个最高级断言（「没有新增」）、每处包含/排除（「除 X 之外」）。
3. **逐条对照正文核查。** 对每条断言，找到支持或反驳它的正文内容。
4. **改整段，而不是只改被点名的短语。** 任何站不住的具体断言都必须就地更正。
5. **重扫孤立引用。** 从摘要里删掉的断言，不得在正文里无对应地重现，反之亦然。

## 何时停止打补丁、改为重写

如果审阅者对同一摘要段落**连续两次**点名（哪怕点的是不同的词），停止打补丁——从结构上重写。同一段被点两次，说明问题出在这段的形状本身，而不是具体措辞。

**重写偏向：** 摘要里宁要抽象，不要具体。一条枚举性断言都不下的摘要，漂移不了。

| 易漂移（具体） | 抗漂移（抽象） |
|------------------------|------------------------|
| 「没有新技能、没有新规则、没有新钩子」 | 「磁盘上没有新目录」 |
| 「27 个技能 / 13 个代理 / 22 条规则 / 6 个钩子」 | 「磁盘清单未变——计数见 README」 |
| 「改动了 `.codebuddy/agents/X.md` 与 `.codebuddy/skills/Y/SKILL.md`」 | 「既有基础设施经修订」 |
| 「修复 Copilot 发现 #3 与 Codex 发现 #7」 | 「处理合并前审读」 |

具体形态新鲜时信息量更大，但更容易烂掉。抽象形态能跨多次编辑保持为真。

## 教训：Copilot / Codex 是漂移探测器

把审阅机器人对同一段落的重复发现当作**结构信号**，而不是一份要一条条打补丁的 bug 清单。每打一次补丁都缩小了漂移窗口，但没有关上它——正文的下一次编辑会在别处重新打开它。

## 两次即止的模式是通用的

「被点两次 → 停止打补丁，升级处理」这条规则不是摘要专属。它适用于任何「分歧可以被每轮悄悄重新糊过去、而不是被解决」的地方：

- `review-paper --adversarial` —— 在第 N 轮与第 N+2 轮提出的同一个关切，会标记给用户，而不是第三次打补丁。
- `audit-reproducibility` —— 一条数值断言在连续两次审计中被降级为 **EXPLAINED**、却从未被更正为 PASS，会显著浮出（"contested number EXPLAINED twice, never corrected"），而不是任它藏在已记录的备注后面。

每一个情形里，两次即止意味着*产物的形状不对*，而不是措辞还需要再摸一下。
