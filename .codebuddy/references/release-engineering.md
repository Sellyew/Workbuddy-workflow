# 发布工程 —— 把研究软件当作产物交付

**本文件回答的问题：** 代码能跑了。在它成为一个*发布版*之前，还有什么是必须为真的——所谓发布版，是一个陌生人能装上、跑起来、用错、然后提一个 bug，而你不在场？写代码不再是慢的那一环；让它的行为**可读、可枚举、被固定**才是。

适用于一个 R 包、一个 Stata `.ado` 包、一个 Python 模块、一个作为带版本产物交付的复现包，以及对某个参考实现的任何移植或重新实现。

---

## 1. 面向用户消息的审计——先普查，后改写

软件展示给人的每一个字符串都是 API——错误、警告、提示、打印的摘要，用户据此决定下一步做什么的那层表面。**机械地把它们枚举出来，并且在动任何一条消息*之前*先把这份普查提交：** 对每一个发出消息的调用点做一遍 grep 加制表——R 里的 `stop()` / `warning()` / `message()`，Python 里的 `raise` / `warnings.warn` / logger 调用，Stata 里的 `display as error` / `error`——写进一个纳入版本控制的文件，记录源路径、行号、类别、条件或返回码，以及**逐字**的文本。

> 一个在改写之后才跑的枚举器，分不清*「原本有四十条坏消息，我把它们修好了」*与*「我找到了我已经修好的那四十条」*。改写前的普查就是分母；没有它，审计就是在给自己的作业打分。

然后把每条消息卡在一个成文标准上——四个问题，用用户的词汇而不是实现的词汇来回答：

| 消息必须说出 | 没说出的失效形态 |
|---|---|
| **发生了什么** | 点了一个用户从没见过的内部对象 |
| **为什么** | 陈述症状，隐藏原因 |
| **对结果意味着什么** | 用户分不清「答案是错的」与「只是外观问题」 |
| **下一步做什么** | 技术准确，操作上无用 |

**任何调用方会据以分支的东西，都要有一个分好类的条件**——一个 R 条件类、一个 Python 异常类型、一个 Stata 返回码——绝不是对文本做子串匹配。一个去 grep 你的错误字符串的下游包，是对你的散文产生了依赖，而你下一次文字编辑就是它的故障。**测试把确切的文本固定住**，于是一次改写就是一次经过审阅的刻意行为，表现为一处测试差异，而不是没人注意到的漂移。

## 2. 静默决策普查

另外单独枚举软件**替用户做了决定**的每一处：

- 参数缺失时选定的一个**默认值**——尤其是*依赖数据*的那种；
- 首选路径不可用时走的一条**退路**（一个换方法的求解器、一个从不同起点重试的优化器）；
- 一次**强制转换**——字符串转数值、字符转因子、一个部分匹配上的选项名；
- **被丢掉的数据**——缺失值、单例分组、零权重单位、被删掉的共线列、被去重的重复键；
- 输入没有规定时**强加的**一个排序、参照水平或平局规则。

每一条只得到两种处置之一：它**说话**——发出一个分好类的条件，并把这一事实记进返回对象——或者它是**有文档的静默**，附一条书面理由说明为什么这些噪音的代价高于沉默。没有第三种处置，而且*「没人抱怨过」*不算理由。

> 用户无法为一个从没被告知做过的决定报 bug。静默决策正是两次「同一个」分析会不同、而没人能重建原因的方式。

**任何改变分析样本的东西，都要是一个返回的数字，而不是一条消息。** 消息会滚走；返回对象里的一个字段会活进日志和复现包。

## 3. 冻结的特性矩阵（移植与重新实现）

一个移植是相对某个参考来评判的，所以那张比较表面必须在移植存在之前就存在。写一张矩阵，**每一条用户可见行为一行**——不是每个函数一行——带上行为 id、参考行为、移植行为、状态（`matched` / `divergent` / `out-of-scope` / `not-yet`），以及对任何不是 `matched` 的项，给出它在 [`provenance-and-ground-truth.md`](provenance-and-ground-truth.md) §3 那张分类表里的分歧 id 与种类。

**冻结**的意思是这张矩阵*支配*移植，而不是描述移植：实现期间发现的一处分歧，先拿到它**经 owner 批准的那一行**，再去实现。反过来，矩阵就退化成「移植碰巧做了什么」的流水账。把它做成一道合并门禁——一个引入了 `divergent` 行却没有批准标记的改动不予合并。两者不一致时谁说了算，是一个提前决定好的优先级问题（[`provenance-and-ground-truth.md`](provenance-and-ground-truth.md) §2）；比较的机械操作见 [`/differential-audit`](../skills/differential-audit/SKILL.md)。

---

## 4. 继承的测试要按名字**和**哈希来声明

如果参考实现有一套测试，你就继承了它。*「我们移植了上游测试」*是一个断言；一份清单才是证据——每个上游测试一行：上游路径、测试名、**该文件在固定提交上的内容哈希**、认领它的本地测试，以及一个状态（`inherited` / `adapted` / `not-applicable`，后者要附理由）。哈希是承重的那一列：只写名字的清单，会在上游*加强*了一个你仍声称满足的测试时静默过期。

**重新同步工具什么都不决定。** 它对固定的上游重新计算哈希，报告每一行哈希移动了的条目，并以非零退出——它不编辑清单、不把行标成 not-applicable、也不重新背书任何东西。一个被允许自行解决其发现的同步工具，最终会把它们全都「解决」掉；而在移动了基线的那个提交里重新背书，会摧毁*已测量*与*已假定*之间的区别（[`provenance-and-ground-truth.md`](provenance-and-ground-truth.md) §6）。

## 5. 发布起飞前的归档

起飞前检查是一份**带日期、带哈希的磁盘记录**，不是「看着还行」的感觉。每份归档包含时间戳、提交、一份**干净树回执**（porcelain 状态的逐字输出，且为空）、环境快照、每道门禁的逐字输出，以及构建载荷的哈希。

**从提交构建载荷——`git archive HEAD` 或等价的导出——绝不从工作树构建。** 从工作目录拼出来的载荷可能包含一个你从未提交的文件，而且它能通过你跑的每一道门禁，因为*你*有那个文件；第一个克隆这个仓库的人没有。这是绿色发布在一个陌生人的机器上崩掉的最常见方式。

**交付的产物必须能重建自己并跑自己的门禁**——载荷带着它的构建入口、它的环境锁定、它的测试入口。只在作者的检出里才能构建的软件，不算发布过；它只是被描述过。

**仅开发用的依赖要用显式标记圈出来**——R 里的 `Suggests` 加 `requireNamespace()` 守卫，Python 里的 dev/extras 分组，Stata 的 ado 依赖另写一步安装说明——并且起飞前检查至少要在一个**只有**运行时依赖的环境里跑一道门禁。否则第一个依赖缺失的错误，就由一个用户、针对一个通过了全部测试的包来报。

留住这些归档——*「我们发出的那个发布通过它自己的门禁了吗？」*这个问题一年后还要能回答。锁定文件本身来自 [`/capture-environment`](../skills/capture-environment/SKILL.md)，载荷离开前的最后一道完整性检查是 [`/verify-artifact`](../skills/verify-artifact/SKILL.md)。

## 6. 下游固定

一个发布在它的消费者把它固定住时才成真。在每个消费者里，核验回执记录的是它那些数字所依据的**提交或内容哈希**——不是版本字符串。版本会被重新打标签；哈希不会。

一个移动了下游所报告数字的改动是**一轮**，包含全部四件事：改动本身；每个移动了的数字的**前／后**证据；重新生成的下游产物；以及重新固定。拆成几轮，就会有一段区间，回执声称了一个它并非据以产生的那次固定。这一轮之内顺序仍然成立——把改动落在一个**旧的**固定值上，好让下游门禁*报告*出漂移，然后在一个引用了那次测量的后续提交里重新固定。改动任何共享之物之前先找出消费者：[`/blast-radius`](../skills/blast-radius/SKILL.md)。

## 7. 状态契约是生成出来的，不是写出来的

文档对软件可能发出的**状态集合**、条件类、警告类或返回码集合所做的任何承诺，都由**工具从源码生成**：一个**生成器**遍历源码、抽出被发出的集合；生成出来的表**作为包数据**交付，运行时即可读，而不只是手册里的散文；再加一个**测试**重新生成并比对，这样一个新加的状态会让构建失败，直到契约被重新生成并通过审阅。

手工维护的状态清单在两个发布之内就会错：某个分支加了一个状态，没人去改 vignette，下游的一次分派就静默落空。这是「每个仓库一个真源，治理永远不随包发布」在发布工程里的实例——[`research-agent-laws.md`](research-agent-laws.md) 法则 17。

---

## 8. 声明过的界限失败时，那是一种处置，不是一个旋钮

起飞前检查声明各种界限：一个性能预算、一个数值容差、一个覆盖率下限、一个内存上限。发布时某一项失败，答案是给出一个**处置**，绝不是去改那个界限——一个靠改写门禁而变绿的门禁，没有改变软件的任何一个字节。对一个预注册的、而证据并不支持的界限，那个处置就是 **WITHDRAW**；降级路径与解除该处置的各项义务在 [`verification-ladder.md`](verification-ladder.md)。

发布工程增加的是那份**记录**：声明时的界限、测量、处置，以及谁批准了它，都放在带日期的起飞前归档里——这样一个带着某项撤回发出的发布，会在下一个人能找到的地方说明这一点。
