# 在研究基础设施上运行代理的法则

提炼自大量代理使用实践：一篇被推到投稿的计量经济学论文、一个带失败即关闭审计面的估计包、多日的模拟战役，以及跨语言移植。**共 21 条法则，每一条都由一次真实事故换来。** 这里没有一条是愿景式的；它就是什么失败了、什么抓到了那次失败，以及防止重演的习惯。

凡是某条法则已在模板别处机械化的地方，交叉引用会说明这一点，而不是重述一遍——一条被说两遍的规则会变成两条互相漂移的规则。

---

## 证据

**1. 断言不是证据。读产物。**
一个代理说*「对比了 33 个值，0 漂移」*是断言；那个 CSV 才是证据。在任何数字进入一个决定或一个读者之前，从一份已提交的产物里把它读出来。用**重新推导**来核验，而不是重新追问。
*事故：*一次确定性检查被报告为覆盖了「完整的 SE 集合」，而对其自身产物做字节检查只显示一个名字；一次审读报告「62 条已确认」，而它的核验者已经驳回了 93 条中的 81 条——一次 join 静默把它们丢了。还有反过来的情形：一次「驳回」某代理表格的抽查，结果证明是检查器自己的错，因为行是按部分键匹配的。**当你的检查与代理不一致时，先怀疑你的检查。**

**2. 先归因，再修复；用阳性对照来证明零结果。**
一道门禁失败或一个数字移动时，先确定是*谁的*改动造成的——在未变的基线上重跑同一项检查。而*「什么都没动」*只有在检测器能在一个已知受影响的情形上确实触发时才算证据。
→ [`verification-ladder.md`](verification-ladder.md) 第 0 级；[`/vaccinate`](../skills/vaccinate/SKILL.md)。

**3. 绝不在移动基线的那个提交里重新背书基线。**
把改动带着旧的固定值落地，好让门禁*报告*出漂移；在一个引用了那次测量的后续提交里重新背书。
→ [`provenance-and-ground-truth.md`](provenance-and-ground-truth.md) §6。

## 绿色结果的范围

**4. 绿色门禁是有范围的。能力丧失对输出等价测试是不可见的。**
一套冻结输出的等价套件，看不见一个静默*不再被产出*的输出。保留一套常驻的骨架，为整个用户可见表面做指纹——每一个数字**及其是否存在**——并在**集合变化**上失败，而不只是数值漂移。
*事故：*一套 70,464 个叶子逐字节一致的套件通过了，而半个诊断工具箱的输出已经消失；常驻指纹立刻抓到了它（13,821 vs 29,748 个数字）。
*实践：*实时发现表面（从 `formals()`、导出，或一份清单），对每个格子做合理性检查（NaN/Inf 即使没有报错也算失败），拒绝对错误的源码树运行，拒绝为没有基线的数字背书。

**5. 一道不可能失败的门禁，比没有门禁更糟**，而且**一项没能跑起来的检查不是通过的检查。**
→ [`verification-ladder.md`](verification-ladder.md) 第 0 级。

**6. 按已实现的实验分派——绝不按标签、请求或封印分派。**
按计算实际做了什么来分支，而不是按被要求了什么、某个字段叫什么名字、或是否有一个认证包装层来分支。**一项能力的可用性，绝不能由一份审计产物来决定。**
*事故：*一个诊断菜单拒绝了合法的未封印拟合，因为一个回执校验器要求封印摘要——审计工具渗进了生产的分派路径。
*推论：*把审计层放在热路径**之外**（按需开启），并把廉价的常开运行记录与昂贵的按需证明分开。

## 授权

**7. 给执行者目标与验收标准——绝不给实现。**
一个被规定的机制，是一个披着指令外衣的假设。陈述目标、标准，以及什么证据能定案；把机制只作为带标签的假设提供，执行者可以拒绝。
*事故，两个方向都有：*一个执行者量出已交付的代码已经达到标准之后，正确地拒绝了一次被规定的重建；而一份没做真值核对就写出的「忠实摘要」，被一个手持逐字原文的敌意裁决者发现含有四处不忠实的陈述。**执行者需要拒绝的余地；审阅者需要手握真值。**
→ [`templates/executor-contract.md`](../../templates/executor-contract.md) —— 这条法则的可派发形态。

**8. 经济性：昂贵的模型做计划与裁决；廉价的执行者跑门禁。**
分解、裁定、精细的散文、不可逆的调用留给最强的模型。执行交给那些质量由**门禁、而非信任**来强制的执行者。长时计算交给花费零 token 的后台进程。不要堆很多并行的船队——限流会产生局部失败。给每个代理：它的工作必须通过的门禁、确切的路径、一份输出契约，以及为每个数字引用一份产物的义务。
*推论：*当一个代理没交付它的契约就停下了，**恢复它并索要报告**——不要重跑那项工作。
→ [`.codebuddy/rules/model-routing.md`](../rules/model-routing.md)。

**9. 把批评／修复循环协议化，否则它会永远转下去。**
有界轮次，带具名信号与责任人：**HOLD**（修复者重试，最多 N 次）、**BLOCK**（升级给编排器）、**STOP**（人）。**两振出局**规则负责升级：同一条发现（同样的 `file` + `locus`，不是同样的 id，因为修复者的编辑会挪动行号、因而挪动 id）熬过第 N 轮与第 N+2 轮，就交给人类，而不是去打第三次补丁（[`orchestrator-protocol.md`](../rules/orchestrator-protocol.md)）。批评者是**靠机制**只读的，不是靠指令。创作者从不自己打分。判定引用不变量数字，这样一个违规是扣分而不是口味之争。
→ [`.codebuddy/rules/orchestrator-protocol.md`](../rules/orchestrator-protocol.md)。

## 长时运行的工作

**10. 长时自主 = 磁盘上的运行手册 + 通知驱动的执行。**
在任何多小时的工作段之前，**先把确切的收尾运行手册**——续跑命令、文件路径、要核对的判定——写进一个受版本控制的计划文件。上下文会被压缩；磁盘不会。一切由完成通知驱动，绝不靠轮询。**监视器必须覆盖每一种终态：**一个只匹配成功行的过滤器，在整个崩溃过程中是沉默的，而沉默看起来与「还在跑」一模一样。ETA 用产物时间戳算，不要凭印象。
*事故：*一次 33 小时、八分片的战役，完全按照写下来的运行手册执行了它的收尾，穿越了好几次上下文压缩。
*实践：***推上去的仓库就是状态报告**——每一阶段落地就提交并推送，包括失败，标注清楚。

**11. 常驻例程：失败时推送，成功时沉默。**
一个每晚都报「一切正常」的作业，训练你忽略它。定时检查只在有事情需要人介入时才报告。
→ [`scheduled-routines.md`](scheduled-routines.md)。

**12. 并行必须可证明地与运行形态无关。**
按**任务**播种，不按 worker 播种：为每个重复预先成一条 RNG 流（L'Ecuyer），使结果在任何核数下都逐字节相同——并且**证明它**：在信任任何战役之前，做一次两核 vs 四核的逐比特一致性检查。按 worker 播种会让结果静默地绑死在执行形态上。
→ [`.codebuddy/rules/simulation-conventions.md`](../rules/simulation-conventions.md)。

## 外部模型

**13. 外部模型咨询是仪器。像操作仪器那样操作它们。**
凭经验找出载荷悬崖，把审读拆成聚焦的单一决策运行——回答本来也更锋利。**核验传输，而不是日志**：唯一已提交发送的信号是产物。**把裁判蒙上眼**——做独立上下文比较之前剥掉修订标记，否则它给的是 diff 而不是文档打分。分别向审阅者索要他们的**最小可接受**版本与理想版本；那个差额才是决策货币。**始终只是参考**——转述之前把每段引文对着源核实，而一条一旦被审阅者从未见过的文件消解的发现，**被划掉，不上报**。
→ [`external-oracle-process.md`](external-oracle-process.md)。

## 记录

**14. 缺陷变成 issue；更正走在最前面；取代是显性的。**
当先前转述的一个断言被证明是错的，**更正就是第一句要说的话**，不是脚注。一起生成的产物要一起重新生成——绝不逐文件地合并解决。当结果以更高保真度重跑时，新产物**显性地取代**旧的，而被取代者原样保留作为记录。
→ [`.codebuddy/rules/issue-ledger.md`](../rules/issue-ledger.md)、[`.codebuddy/rules/progress-reports.md`](../rules/progress-reports.md)。

**15. 记忆需要一个捕获门禁和一套提升政策。**
任何东西被记住之前先问五个问题：**持久吗？不显然吗？稳定吗？具体吗？还没被记录过吗？** 以防万一型的记忆被禁止——它们污染索引，让有用的那些变得找不到。从本机观察到已提交知识的提升是一次**经过审阅的行为**，不是自动保存。
→ [`.codebuddy/skills/promote-memory/SKILL.md`](../skills/promote-memory/SKILL.md)。

**16. 规则与它所治理的代码同住；共享规则要声明它的上游。**
一个被每道审计门禁治理的包，**自己一条防线都没有**——它的全部规则都住在消费者仓库里，任何直接在这个包上开会话的人都看不见。在被治理的仓库里放一个最小的 `.codebuddy/`。而每条跨仓库共享的规则都带一个**规范上游标记**：一次调查发现同一条规则的五个副本跨度 61–194 行，无从判断哪份是当前的；还有一条规则在两个仓库里做出**相反的事实断言**。

**17. 每个仓库一个真源；治理永不随包发布。**
每个事实只在恰好一个地方陈述。治理脚手架留在发布产物之外。
→ [`.codebuddy/references/model-versions.md`](model-versions.md) 是这套模板的实例。

## 最后一公里

**18. 计数是一次计算，不是一次阅读。**
每一个到达决策者面前的数字，都**由一条命令产出、其输出就是这个数字**——`wc -l`、某脚本的最后一行汇总、一个返回总数的查询——并且它*连同*推导出它的那条命令一起报告。一个从滚动过的终端里抄下来的数字、一个被截断的工具结果、或一段「大概过了多少行」的回忆，不是计数；那是一个披着计数精度的猜测。
*事故：*一个代理报告 **10** 行失败的断言，而产物里有 **25** 行——控制台被截断了，被总结的是可见的那部分；这个数字在一次会话里被往回改了两次。产物存在且正确。失败在于用眼睛去读它。
*实践：*模板把文档那一半机械化了——[`scripts/check-derived-counts.py`](../../scripts/check-derived-counts.py) 从各自的真源重算文档里每一条可枚举断言——但这条法则比任何检查器都宽。
*范围，因为宽读比法则本身更糟：*它约束的是**一个决定或一个读者据以立身**的数字——任何被发表的东西、任何给某个选择设门禁的东西、任何会被别人引用的东西。它**不是**要求对话里的每个数字都附带一条命令；一位外部审稿人的合理反对是：一条被读得那么宽的规则，会产出仪式性的 `wc -l` 调用，什么也证明不了，还训练你去忽略它们。如果那个数字只是给你定个方位、错了也只是重读一遍，那就说出来然后继续。如果错了会传播，就把它推导出来。

**19. 说出你实际到达的状态；绝不说更晚的那个。**
「做完了」把五种不同的状态压成一个词，而这个词通常是错的。报告那个真实存在的：

| 状态 | 什么是真的 |
|---|---|
| **modified** | 请求的改动存在于工作树里 |
| **verified** | 具名的门禁已经**跑过**并通过 |
| **committed** | 存在一个提交哈希 |
| **pushed** | 一个具名的远端 ref 含有那个提交 |
| **integrated** | 预期的目标——一个分支、一个发布、一个已部署的页面——含有它 |

声称一个比实际到达的更晚的状态，就是整个缺陷：*「实现了，门禁应该会过」*是一个附了完成通知的假设，而一道留给 pre-commit 钩子去发现的门禁，是你没跑过的门禁。钩子抓的是例外；它们不是工作流。
*事故：*一个交付物到达回合边界时，它的渲染验证从未跑过；只有 Stop 钩子挡住了这次报告，代价是一次计划外的往返。钩子起了作用——而它*不得不*起作用，正是这条法则要消除的缺陷。
*任务在哪里结束是任务自己的事，不归这条法则管。*早先的一版草稿要求每个任务都以 **pushed** 结束；一位外部审稿人指出，这会伤害一个要求看工作树 diff 的合作者、一个没有推送权限的贡献者，以及任何离线的人——完成状态属于契约，只有报告的诚实属于这里。在提交需要明确签核的地方（[`/commit`](../skills/commit/SKILL.md)），一个被授权的任务以 **verified** 结束并带着证据交回；提交是它自己那个被授权的步骤。
→ [`.codebuddy/rules/progress-reports.md`](../rules/progress-reports.md)。

**20. 历史操作通常从一个 porcelain 干净的工作树开始；例外是一次显式的越权，并作为例外被报告。**
先跑 `git status --porcelain`。如果它打印了任何东西，就提交它，或把它 stash 在一个说明了它是什么的标签下，然后再合并。论点不是 git 会可靠地摧毁脏工作——它常常拒绝碰有冲突的本地改动——而是：在一个未提交的状态之上做整合，**摧毁了归因与可审查性**，并让冲突解决过程中的意外共同暂存更可能发生。事后，没有任何东西能区分「你选择的」与「本来就摆在那里的」。
*事故：*一次对一个脏的**共享**工作树尝试的快进合并中途失败，逼出一次临时的 stash 加恢复，还要手工保住分支——本来五秒钟的 porcelain 检查就能省掉这次恢复。在共享树上，那些脏东西甚至可能不是你的。
*这条法则绝不能让你相信的三件事*，确立其中每一件都花掉了一轮审阅：朴素的 `git stash push -m …` **不**会 stash 未跟踪文件（当 `??` 条目正是你要寄存的东西时，用 `-u`）；`--autostash` **不是**通用的干净树操作，理由同上；而一次执行前检查只能确立「在**命令被授权的那一刻**树是干净的」，除非复合形式被直接拒绝。
*已机械化：*[`.codebuddy/hooks/git-guardrails.py`](../hooks/git-guardrails.py) 在树脏时拒绝该操作，并且只把历史操作当作独立命令接受——这样一条在操作之前弄脏树的链，就无法从决定与执行之间的缝隙里溜过去。逃生口是 `ALLOW_DIRTY_MERGE=1`：刻意的显式行为，而且用它时值得说出来。

## 筛选与波次

**21. 被授权的筛选在成文细则下运行；一波整体裁定。**
一个筛选代理在**运行之前**就拿到它的细则**书面版本**：纳入与排除标准、**一个声明好的默认判定**，以及每个候选都必须带着自己的证据回来、而不是一个裸判定的要求。

**选哪个默认是一个决定，不是一个常量。** 下面那次事故产出了一个漂向宽松的筛选，所以*那个*筛选想要默认 EXCLUDE——一次假纳入的代价是把整个语料手工重筛一遍。把代价反过来，答案也就反过来：在一个**召回优先**的筛选上——一次文献扫读、一次在先技术检索、任何在问*我们漏了什么*的任务——默认排除会静默丢掉相关证据，而与一次坏纳入不同，**下游永远不会有任何东西把它翻出来。** 一位外部审稿人恰好把这一点标为「一条经验法则如何变成研究质量缺陷」。所以：在细则里命名那个默认，并通过问「你日后还抓得住哪个错误」来命名它。当两个错误都不可挽回时，诚实的默认是第三种判定——NEEDS-HUMAN——而不是一枚朝齐整那边加权的硬币。

然后派发方**对着同一份细则抽查一个样本**——一次没人复查的筛选，是一次带着引文的民意测验。「抽查」这个说法不够可证伪：在五分之一的排除是错的时候，确认三个明显的纳入什么也证明不了，而宽松筛选实际呈现的正是这个形状。所以在筛选运行之前就声明协议——**样本怎么抽（随机或分层，绝不手挑）、排除项与边界项被刻意过度抽样、样本量、你能接受的分歧率，以及超过它时怎么办。** 缺了这五项，复查就不可能失败，而一道不可能失败的检查比没有更糟（法则 5）。

一波平行的代理**一次、整体**裁定：早到的返回是*状态*，不是输入，而判定按 **id** 接到候选上，绝不按模型写的字符串（法则 1 里那次静默 join 就是同一个缺陷降了一层）。有一个例外，而且它不是锚定：早期证据可以触发一次**协议级中止**——如果最初的返回显示细则含糊、输入被污染，或每个 worker 都误读了同一条标准，就中止这一波。拒绝看早期的*判定*是规则；拒绝注意到这次运行已经坏了，只是浪费。
*事故：*一次没有书面细则的被授权筛选回来时太宽松，整个语料只能在更严格的标准下手工重筛——缺失的细则让整个筛选付了两次代价。同一份遥测对波次的说法很直白：做了整波裁定的会话都走得不错；那个把第一个返回照单全收的扇出，只能重做。
*实践：*细则照 [`templates/screening-rubric.md`](../../templates/screening-rubric.md) 写，派发照 [`templates/executor-contract.md`](../../templates/executor-contract.md) 写。
