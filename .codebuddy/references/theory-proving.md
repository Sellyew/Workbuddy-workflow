# 攻克理论问题——证明契约、组合搜索、对抗式审计

面向计量理论：识别论证、渐近结果、论文附录里的证明、反例搜寻，以及「这个猜想到底成不成立？」这类工作。本文件改编自 2026 年 7 月解决了若干 Erdős 开放问题的开放问题工作流（Shouqiao Wang 的方法，在 `meleantonio/open-problem-prover` 中一般化，两者均为 MIT）——这些技术几乎原样迁移到统计学与计量经济学，因为失败模式是同一批：看起来合理的论证，经不起一次敌意阅读。

> **AI 生成的证明是一个断言，不是一个定理。** 这套工作流的全部设计目标，就是让错误的证明很难活下来。预期有相当大比例的精心挑选的尝试会失败——那是方法在起作用，不是方法失败。

## 1. 证明契约——在任何证明之前

在第一份尝试之前，先写一份文档，定义*究竟什么才算一个解*：

- **用本模板的记号精确重述**，每个假设都显式写出。
- **肯定与否定的双重判解标准**——什么能证明它，什么能否证它。两个方向都要活着；一个反例和一份证明一样可发表。
- **已知背景，以及它并不蕴含什么。**计量理论里最常见的失败，是静默地引入一个被引结果并不给予的结论（在需要一致的地方只用逐点；在设计有聚类的地方当成 iid；没人假设过的紧性）。
- **一道「不足的近似物」防火墙。** 把那些看起来像证明、其实不是的论证列出来：未加论证地交换极限、「由标准论证」、没有速率就把插件估计量的误差当成二阶、把边界情形假设掉（无界权重、倾向得分里的原子、退化方差）。
- **问题特有的陷阱。** 半参数情形：那个悄悄假定了比所述更多光滑性的切空间计算；自助法断言：没人重述过的原假设下会变的中心化。
- **退出标准。** 什么结束这次尝试——一份证明、一个反例，或一条点明了确切缺失引理的具名被堵路线。*一条被堵的路线是一个科学结果。*

## 2. 组合搜索——独立路线，一本路线台账

**独立地**探索真正不同的证明策略——分叉出的、看不到彼此笔记、也看不到那条受偏爱路线的独立代理（共享上下文会产生「靠模仿的收敛，而不是靠正确性」；实证工作里量到的同一种羊群效应，在证明里同样适用）。

在**一本路线台账**里追踪每条路线：路线、状态（live / blocked-at / merged）、它被卡住时那个确切的定理强度缺口，以及产物。**要求产物；拒绝状态报告**——「在实证过程那条路线上取得进展」不是一条台账条目。

## 3. 计算作为证据——先给自己的引理找反例

在投入去证明一个引理之前，**先试着用数值打破它**。对计量经济学来说这既便宜又残酷：小小的对抗式设计——两期、三个单位、倾向得分里的一个原子、裁剪边界上的权重、方差为零。一个熬过一套设计好的网格的引理，配得上一份证明尝试；一个失败的，替你省了一周。

- **任何被报告的东西都用精确算术**（有理数、符号代数）——浮点在边界上什么也证明不了，而边界正是计量引理死掉的地方。
- 有限子问题（组合式的识别论证、小设计上的界）常常可以靠穷举完全解决——那是一份**有限证书**，不是一次模拟。
- 既定规则：**计算是证据，除非它被转成严格证明或一份有限证书。**一次支持某猜想的模拟进台账当证据，绝不进论文当证明。

## 4. 对抗式审计——每份草稿配一个全新的敌意审稿人

每份草稿都由**一个只看得到契约与草稿的独立上下文代理**审计——绝不给它探索历史（它会继承同一批盲点）。审计者：

- **逐条**走那份防火墙与陷阱清单；
- **展开每一个「显然」「标准」「容易看出」**——那正是证明死掉的地方；
- 在可算的对抗式实例上独立重算承重步骤；
- 按本模板的契约返回发现：位置 + 缺陷 + **失败案例**（打破该步骤的具体配置，或那个确切缺失的假设）。

循环：*尝试 → 失败 → 诊断 → 新路线 → 草稿 → 审计 → 修复*——在标准的收敛规则下（[`verification-ladder.md`](verification-ladder.md)：成批修复，连续两轮没有新增已确认缺陷就停，两振出局升级给人）。

## 5. 核验与披露

- 论文带**显式的引理依赖**——一张依赖图，这样一个坏引理的爆炸半径是可知道的（[`/blast-radius`](../skills/blast-radius/SKILL.md) 对证明同样适用）。
- 每个计算性断言配一个**伴生核验脚本**，并说明它**不**检查什么。
- **只要可行就用 Lean 形式化**——重，但它存在，而且它是唯一一道没法争辩的门禁。对大多数计量理论，现实的目标是形式化组合式或有限维的核心，而不是整个渐近论证。
- **任何公开断言之前要有一道人的关卡。** 外部裁判（[`external-oracle-process.md`](external-oracle-process.md)）是一份完成草稿天然的确认审稿人——在内部审计之后，绝不代替它。

## 这与既有内容如何组合

| 本工作流的部件 | 既有的机械装置 |
|---|---|
| 证明契约 | 预先提交的解释（[`verification-ladder.md`](verification-ladder.md) 第 5 级） |
| 路线台账 | 设定搜索台账，用在证明路线上 |
| 隔离的探索者 | 独立性那一级——独立上下文代理 |
| 对抗式审计 | [`/deep-audit`](../skills/deep-audit/SKILL.md) 偏反驳的核验者 + FINDING 契约 |
| 「计算是证据」 | 五个可信度问题——一个问题的证据永远不能为另一个结清 |
| 末尾的外部审稿人 | [`/oracle-review`](../skills/oracle-review/SKILL.md) —— 确认，不是发现 |

**刻意不装成插件。** 迁移的是方法；上面的工具已经实现了它的大部分。如果你想要上游的斜杠命令，它提供 `install.sh` 与一个市场——对着 [`provenance-and-ground-truth.md`](provenance-and-ground-truth.md) §7 评估一下（两个仓库都是 MIT，所以带署名的复用是干净的）。
