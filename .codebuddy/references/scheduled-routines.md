# 定时与后台例程

工作流中「循环优先」的那一半：那些应当*按计划*运行、并且只在找到东西时才现身的反复性学术杂务——而不是在你想起来去跑它们的时候才现身。这些是 **Routines**（由 `/schedule` 管理的定时远程代理），不是提交进仓库的 cron 文件，所以它们能在笔记本合上时活着，并跑在 web 基础设施上。

> **凡是离开键盘的工作，用 Routines，不用 `CronCreate`**——Routines 跑在受管基础设施上并能持久；本地 cron 会随 REPL 一起死。下面每个例程都是*提示词 + 间隔*；用 `/schedule` 设置一次即可。**一个例外：**收件箱分诊作为你机器上的 Desktop 定时任务运行，因为它的摘要与审稿人跟踪表被 gitignore 且是本机的，扛不过 routine 的一次全新克隆。

## 常驻例程（以及一个提醒）

| 例程 | 间隔 | 它做什么 | 何时推送 |
|---|---|---|---|
| **可复现性漂移** | 每晚 | 对着护照重跑 `/audit-reproducibility`；对过期的断言做差异 | 任何 FAIL（非 EXPLAINED） |
| **文献增量** | 每周 | 对你保存的题目跑 `/lit-review` 扫读；与上周做差异 | 出现新的直接相关工作 |
| **记忆提升** | 每月——**一个提醒，不是例程** | 你在本地会话里自己跑 `/promote-memory`：它由用户调用，而它的候选住在本机的自动记忆里，云端例程看不到 | 有条目升级进 MEMORY.md |
| **收件箱分诊** | 每日／工作日——**一个 Desktop 定时任务（本地），不是云端例程** | `/triage-inbox`——审稿请求、R&R 截止日、合作者的事。它的摘要与审稿人跟踪表被 gitignore 且是本机的，所以云端例程的全新克隆会从没有跟踪表开始，并丢掉摘要 | 提出一个动作（始终由人把关） |

**定时任务无法触发一个由用户调用的技能。** 标了 `disable-model-invocation: true` 的技能（例如 `/triage-inbox`、`/promote-memory`）在定时任务——云端例程或 Desktop 任务——把它们当作提示词指名时不会运行。对这类技能，把提示词写成「读 `.codebuddy/skills/<name>/SKILL.md` 并照它做」——任务的检出里有这个文件——或者你自己手动跑。

**失败时推送，成功时沉默。** 一个每晚都发邮件说「一切正常」的作业，训练你忽略它。这些只在真有发现时通知；一次安静运行除了一行日志不留任何痕迹。

## 事件驱动，不只是定时

每晚的可复现性作业是*兜底*。*即时*信号是 [`claim-reconcile`](../hooks/claim-reconcile.py) 这个 PostToolUse 钩子：一个分析脚本或 `output/` 产物一改，它就把依赖它的稿件断言标记为可能过期，并把你指向 `/audit-reproducibility`——这样你在分析过程中就抓到漂移，而不是第二天早上。对*外部*的重新生成（你在 Claude 之外跑了 `Rscript`），harness 的 `FileChanged` 钩子事件可以驱动同一项检查；如果你的工作流在工具层之外重新生成输出，就在 `.codebuddy/settings.json` 里把它接上。

## 设置一个

`/schedule` 接受**自然语言描述**，不接受旗标：

```text
/schedule nightly at 6am: run /audit-reproducibility against the current passport.
If any claim FAILs (not EXPLAINED), summarize which tables are affected and notify me;
otherwise exit quietly.
```

一个精确的 cron 表达式（例如 `0 6 * * *`）在例程存在*之后*通过 `/schedule update` 施加；用 `/schedule list` / `update` / `remove` 管理。设计时要绕开两个调度约束：**最小间隔是 1 小时**，而且账号有**每日运行上限**——所以要把检查合并进一个例程，而不是做很多小例程。Routines 作用于**已提交的仓库**：任何未提交或设计上私有的东西（例如一个本地研究库）对它们是不可见的。

`scripts/nightly-repro-check.sh` 是每晚可复现性检查的**本地**运行器——只要数据在本地或未提交，它就是必需的而非可选项（云端例程拿到的是全新克隆，够不到你的数据目录；见下面的机制表）。用 Desktop 定时任务或机器 cron 来调度它。`/schedule`（云端）只适合完全已提交的仓库。

## 无人值守运行的防线

- **绝不让一个无人值守的循环在没有人的关卡的情况下对着投稿门户、共享／受限数据，或合作者的收件箱。** Routines *提议*；人*发送*。（`/triage-inbox` 从不自动发送；[`git-guardrails`](../hooks/git-guardrails.py) 钩子在例程里仍然阻挡破坏性的 git 操作。）
- **说清「完成」是什么意思，以及你要哪些停止方式。** 在无人值守运行里，当前的 Opus 有时会用一份进度报告结束一个回合，而不是下一步（Anthropic 的 Opus 5.5 提示指南，「Unattended agentic runs」）。把完成条件写进例程提示词，并点明唯一可接受的停止方式——例如「继续直到每条断言都被重新检查；只有在某一步被卡住时才提前停，并说明卡在哪」——同时对任何有风险或不可逆的事保留人的关卡。
- **给成本设界。** 每晚做一次全稿重新审计没问题；每晚做一次 7× `/seven-pass-review` 不行——先做成本试点。
- **连接器默认「全包含」——给它们最小权限。** 云端 Routines 运行时**挂着你的全部 claude.ai 连接器，含写权限，且没有批准提示**。一个只需要读你仓库的无人值守例程，应当在它开火之前就把 Gmail/Calendar/Slack *从那个例程的连接器清单里移除*——风险不在于缺一个连接器，而在于一个满配的连接器在你不在时行动。（*终端*会话里本地认证的 MCP server 是另一回事，在其他无头语境里也可能不在——两种情况都要优雅降级。）

## 选择调度机制（2026-08-21 核对）

上游 Claude Code 提供**三种**调度工作的方式。对研究而言要紧的区别是**本地文件访问**——云端例程对着*全新克隆*运行，看不到本地或受限数据。

| | 云端 routines | Desktop 定时任务 | `/loop` |
|---|---|---|---|
| 跑在 | Anthropic 受管云 | 你的机器 | 你的机器 |
| 需要机器开着 | 否 | **是** | 是 |
| 需要会话开着 | 否 | **否** | **是** |
| 跨重启持久 | 是 | 是 | 未过期时在 `--resume` 上恢复 |
| **访问本地文件** | **否（全新克隆）** | **是** | 是 |
| 权限提示 | 无（自主） | 按任务可配置 | 继承会话 |
| 最小间隔 | **1 小时** | 1 分钟 | 1 分钟 |

### 这对研究工作流意味着什么

- **对本地数据的每晚可复现性检查** → **Desktop 定时任务**。云端例程拿到全新克隆，够不到你的数据目录。这才是 `scripts/nightly-repro-check.sh` 的正确归宿。
- **受限使用的微观数据** → **仅 Desktop**，绝不云端。云端例程需要数据在仓库里，而保密数据规则禁止这样做。
- **盯一个 PR、一次 CI 运行，或一次长构建** → 云端 routines（不需要机器开着），或如果你已在会话里就用 `/loop`。
- **活跃会话内的轮询** → `/loop`。它随会话而死；对轮询没问题，对任何必须挺过重启的事就是错的。

> 会话范围内的调度仍然是会话范围内的：*「任务是会话范围内的：它们活在当前对话里，你开一个新对话它们就停。」*2026-08-21 重新核对——那条由来已久的指导仍然成立：任何必须活得比会话更久的事，都用持久调度。

### 最小权限仍然适用

云端 routines 默认**包含全部有写权限的连接器**。按任务授权，不按账号授权。

## 失败时推送，成功时沉默

**一个每晚报「一切正常」的作业，训练你忽略它。** 等它真报出什么的时候，它已经当了一个月的噪音，你一眼扫过去就略过了。

定时检查**只在需要人时**通知：

- **失败** → 推送一条通知，带上失败的门禁、产物路径，以及复现的命令。
- **成功** → 写日志，什么都不说。
- **没跑** → 这是**失败**，不是沉默。一项没能跑起来的检查不是通过的检查，而一个静默死掉的调度器，与一个报告干净的调度器无法区分。心跳缺失要像红灯门禁一样大声告警。

与「监视器过滤器要覆盖每一种终态」是同一条原则：一个只匹配成功行的过滤器，在整个崩溃过程中都是沉默的，而**沉默看起来与「还在跑」一模一样**。
