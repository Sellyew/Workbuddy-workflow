# 溯源与真值

**本文件回答的问题：**当你说「数字对上了」，*对上了什么*？一个估计值的好坏，取决于你拿它比对的那个东西。本文件讲的是如何命名那个东西、如何把它固定下来，以及当两个来源互相冲突时如何判定谁赢。

适用场景：把一个估计量移植到另一种语言、复现一篇已发表的论文、重新实现一个方法、升级一个包版本，或采用外部来源的材料。

---

## 1. 给你的 oracle 命名，带上角色与固定提交

不要只说「我们和 R 比对过」。画一张表，放在 `quality_reports/PROVENANCE.md`（复制 `templates/PROVENANCE.md`；放在仓库根目录会被 `check-repo-hygiene.py` 判为根目录杂物，除非你把它加进 `ROOT_ALLOW`）：

| 参考 | 角色 | 观测到的 ref |
|---|---|---|
| `owner/canonical-pkg` | **主要的统计与 API oracle** | HEAD `9aba07d…`；版本 2.5.1 |
| `owner/other-impl` | 更深测试的来源 | HEAD `555f28b…` |
| `owner/legacy` | 遗留行为的来源 | HEAD `fdbae25…` |
| `owner/published-paper` | 实证验收套件 | HEAD `50f4f18…` |
| `owner/eng-ref` | 工程参考（只作风格／架构） | HEAD `f8e303d…` |

**要固定提交 SHA，不要版本字符串。** 版本会被重新打标签；提交不会。只要可行，就把 oracle 留成工作旁边的**物理检出**——一个真的以那个固定发行版命名的目录，让「和什么比过？」这个问题没有歧义。

逐个参考记录**许可证说明**，包括诚实地记下含糊之处：*「classifiers 提到 Apache，而 `setup.py` 说 MIT——澄清之前以 MIT 为准。」*

## 2. 在测量*之前*声明优先级

两个 oracle 迟早会不一致。**提前**决定谁说了算，否则你就会在看到自己更喜欢哪个答案之后才决定。

> `impl-B` 抛错而 `impl-A` 只是警告——**一致性判定由 `impl-A` 说了算。**
> `impl-B` 期待有限标准误而 `impl-A` 返回缺失——**`impl-A` 说了算。**

也要写下通用规则：*R 是基准；Stata 与 Python 的移植必须与 R 对齐，而不是反过来。*

---

## 3. 不是每一处差异都是 bug——给分歧分类

在一个纳入版本控制的 `divergence-kinds.csv` 里，给每处分歧一个**稳定的 ID** 和一个**种类**：

| 种类 | 含义 |
|---|---|
| `behavioral-default` | 两者都正确；默认值不同（例如某个实现默认施加小样本校正；不同的默认带宽选择器） |
| `language-surface` | 该构念在目标语言里没有对应物 |
| `stata-surface` / `api-surface` | 源实现暴露了移植版刻意不暴露的东西 |
| `internal-api` | 一个未导出的内部项，不在一致性范围内 |
| `test-placement` | 由另一个 fixture 覆盖，并非缺失 |
| `upstream-conflict` | 参考之间互相不一致 → 由优先级规则裁决 |

```csv
divergence_id,divergence_kind,summary
F051-DIV001,behavioral-default,port applies HC1 small-sample correction by default; reference defaults to HC3
F051-DIV002,behavioral-default,port defaults to analytic SEs; reference defaults to bootstrap
PY010-DIV002,upstream-conflict,Python raises where R warns; R governs parity decisions
```

一处 `behavioral-default` 分歧是**记录，不是修复**。这是 `EXPLAINED` 处置在跨实现情形下的形态：一个有名字、站得住脚的替代做法不是失败。

---

## 4. 覆盖率是一份清单，不是一个样本

不要让审阅者——无论人还是模型——挑要检查什么。把表面枚举出来，并跨轮追踪覆盖：把上游包**自己的测试套件**做成 CSV、一张特性矩阵、fixture schema，以及声明好的性能预算。然后每一轮*指派*要覆盖什么。

---

## 5. 容差是声明出来的，不是试出来的

维护一份**容差登记表**：每次比较，容差是多少、为什么。*在*比较*之前*就把容差定死，否则你会一直调到答案变成你想要的那个。

> **`all.equal` 的尺度陷阱（R）。** `all.equal` 只在**有差异的那些元素**上计算平均量级；当这个均值低于 `tolerance` 时，比较就静默变成**绝对**比较——于是一个大部分尺度良好的大向量，只要那些不同的格子恰好很小（标准误恰好就住在那里），陷阱就会触发。显式传 `scale = max(mean(abs(target)), .Machine$double.eps)`，并用一条 `tested-set == registered-set` 断言给每个一致性文件收尾，这样一个被静默跳过的比较就不可能被读成通过。

## 6. 绝不在移动基线的那个提交里重新背书基线

把改动**带着旧的固定值**落地，让门禁**报告**出这次漂移。在一个**引用了那次测量的后续提交**里重新背书。在重新背书那个提交*之前*让门禁变绿，不是在之后。

在造成改动的那个提交里重新背书，会留下一个**分不清「先测量、再重背书」与「没测量就重背书」**的产物。那种含糊本身就是缺陷，即使数字当时是对的。

**先归因，再修复。** 一个数字移动时，先确定是*谁的*改动造成的——在未变的基线上重跑同一项检查。而*「什么都没动」*只有在检测器能在一个已知受影响的情形上确实触发（**阳性对照**）时才算证据。

**追踪每次比较的两侧。** 一份从未纳入版本控制的固定清单，是一次右手边住在某个工作树里的比较——不可复现。

## 7. 净室边界（合法地使用别人的工作）

| 产物类别 | 允许的来源 | 复制政策 |
|---|---|---|
| 契约文档 | 从观察到的行为出发的原创综合 | 归本仓库所有 |
| 参考锁定 | 来自公开仓库的提交／版本元数据 | 归本仓库所有 |
| Fixture 输入 | 在这里生成 | 自有；生成器有记录 |
| 参考的期望输出 | 从固定的 oracle 生成 | **允许作为测试 oracle** |
| 实现代码 | 新写的，在这里写 | **不得复制**，除非有一条台账条目记录来源路径、提交、许可证、复制的行、理由，以及一个许可证兼容的决定 |

参考代码可以为了理解公开行为、测试、架构与风格而被**阅读**。**生成的数值输出、清单、行为描述与公开文档可以用作测试 oracle。** 实现代码不得复制。

**许可证兼容是一道门禁，不是一条脚注。** 把 copyleft 许可的文本或代码复制进一个宽松许可的仓库而不遵守 copyleft 条款，无论多有用都是违规（LGPL 的链接豁免并不覆盖把源码复制进 MIT 树）。要么独立地重新实现那个*想法*并作为在先技术致谢，要么取得许可并把它记进台账。

---

## 8. 证据契约——让好报告成为你唯一能提交的那种

把门槛编码成一个 issue 模板，这样一份不完整的报告在*构造上*就是不完整的。对一个数值差异，要求：包版本 · 平台 · 确切的命令 · **参考命令及其输出** · 设计细节（面板还是重复截面、分组、期数、协变量、权重、聚类、bootstrap、聚合）· 观察到的差异**以及期望的容差** · 一个可复现的 fixture。

写下政策：*没有复现器、没有数据描述、没有参考比较的报告，可以以「不完整」为由关闭。*
