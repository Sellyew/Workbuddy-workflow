# 深度对抗式审计

对缓慢的逐轮审查给出一个收敛式的替代方案。与其让一个审查者每遍找出一两个问题，不如一次把许多相互独立的怀疑者铺到*整个*产物上，裁定他们找到的东西，修好所有被确认的，再重新验证。它仿照的是硬核形式化证明攻关背后的多代理方法论（多样化独立组合、全程对抗、只认具体证据、综合—挑战—再重复）。

## 什么时候该用它
- 产物密到单遍审查每跑一次都还在冒出*新*问题（这就是逐轮审查用错工具的迹象）。
- 正确性是首要目标，漏掉一个缺陷代价很高（投往顶会/顶刊的论文、一份证明、一处安全敏感的改动、一次迁移）。
- 用户要求 "fix ALL of it"、"be deeper"、"converge faster"、"100% rock solid"。

需要用户已选择启用多代理编排（他们要求过工作流／深度审计／扇出代理，或 ultracode 已打开）。若还没有，先提出这个方案及其大致成本。

## 方法

**1. 拆解（多样化组合）。** 按*想法*而不是按章节把产物拆成组件：每条独立论断、引理、估计量、子系统、不变量。再加上横切的*失效模式透镜*（见下文）。覆盖目标定为：每一条承重论断都至少被一个正对着它看的代理攻击过。不要把你自己偏好的读法告诉代理——保住独立性，免得它们全都收敛到同一个诱人但错误的结论。

**2. 扇出对抗式查找者（每个组件一个）。** 每个查找者都被要求去*反驳*，默认立场是"这里有 bug"，并且必须把每一条主张都落在真实的正文／代码上（去读它，不要凭记忆转述）。硬性规则，取自被验证有效的做法：
   - **只收具体发现。** 每条发现 = 确切位置（file:line / label + 引文）+ 一句话缺陷 + 一个**失败用例**（具体输入/配置 → 错误输出，或确切缺失的那条假设）。
   - **拒收**状态汇报、"looks fine"、"this is standard/routine"、含糊的乐观，以及 "the global step is straightforward."。
   - **把同一困难挪到别处、或预设自己结论的修法，不是修法**——把它标出来。
   - 若认真攻击之后一无所获，该代理必须列出它实际跑过的*具体*攻击以及每一次为何闭合——不能只说 "clean"。

**3. 裁定每一条发现（独立裁判者）。** 一名独立的裁判者重新打开每个被引用的位置，判定 CONFIRMED / REFUTED / DOWNGRADED，对*产物与发现*两者都保持怀疑。这一步杀掉假阳性（误读、假设其实在别处已经给出、在所述条件下根本不会发生的失败用例）——正是它让修复清单保持诚实。

**4. 综合。** 按位置去重，按 fatal > major > minor 排序，交回一份干净的缺陷清单。任何东西在通过这一步之前都不算问题。

**5. 修好所有被确认项，然后重新验证。** 落实每一条被确认的修复（由你，在主循环里——修复需要细心与判断）。然后重新审计被触及的位置，检查没有哪条修复造出新的缺陷。反复成波推进，直到**连续两轮**审计都返回空（兜底上限：5 波；一条在波次 N 与 N+2 都存活的发现交给用户，而不是再打第三次补丁）。不要在第一波之后就停。

## 失效模式透镜（按领域调整）
除逐组件的攻击之外，还要显式扫这些横切模式——真正的缺陷就藏在这里：
- **过度声称：** 标题/摘要声称的，超过定理/检验实际交付的。
- **证明中的越界：** 在需要*一致*结论的地方用了*逐点*结论；把一个*双向都成立*的性质不加限定地陈述；把特例论证当一般论证用。
- **沉默的假设：** 用到却从未陈述的可微/稠密/连续/有界/正值条件（数学中），或未经检查的前置条件/不变量（代码中）。
- **边界情形：** 原子/并列、端点/无界支撑、空/退化输入、参数空间的边界。
- **循环：** 预设自身结论的假设；引用自身的结果；支撑力不及所声称的引文（去读被引的那一份）。
- **内部矛盾：** 同一处定义/记号有两种用法；某个表格单元与命题相悖；正文与附录不一致；悬空或错误的交叉引用。

## 全新眼光一遍（终闸）
每一波定向审计都继承了写它提示词的人的盲点：聚焦提示、修复历史、预期失效模式，都把审计者往已知地带上引。**在所有定向波次与修复都做完之后，跑一次几乎不给上下文的冷启动审计**：独立审计者只拿到产物和一句极简指令（"find concrete defects: location + failing case"），没有聚类分配、没有历史、没有特别关注清单。只让*入口*多样化（像期刊审稿人那样正文优先；附录优先；表格/论断优先；以及审计者自选的单点深潜）。照常裁定。干净的全新眼光一遍 + 干净的定向覆盖 + 全绿的机械检查组，就是收口标准；若全新眼光一遍找到了定向波次漏掉的东西，那也是对这套提示词的诊断——把漏掉的失效模式补进透镜。

## 全量清单——绝不抽样
对论文/证明类产物：**先把每一条形式化陈述列全**（grep `\begin{theorem|proposition|lemma|corollary}` + labels），并把每个证明指派给一个验证者——覆盖必须是承重陈述的 100%，而不是"审查者挑的少数几个证明"。抽样是线性且随机地收敛；清单则一波收敛。把紧耦合的小引理归成簇；大证明单独配验证者。每个验证者除审查发现外，还要返回一份**已验证步骤清单**和一个**假设台账**（用到 vs 已陈述；用到但未陈述即为一条发现）。

## 机械检查组（产出最高的检查）
写下来的论证读起来可以很扎实，而它所定义的对象却是错的。对**每一个估计方程、影响函数恒等式、识别论断与总体矩**，都写一个可执行检查，在对抗式的玩具设计上*算出那个总体对象*——截断（删失端点落在结果端点之下）、内部原子、错误设定的干扰项、边界/重叠失败——并用数值方式断言所声称的中心化/恒等关系（解析，或固定种子的细网格/大 N）。把这些脚本作为仓库里一个常设的测试目录并配 README 保留；相应公式一改就重跑。一段五行的总体计算就能抓住一整类缺陷（尾部重归一化的根、符号翻转、质量亏空加权），而无论细心阅读还是模型共识，抓它们都不可靠。

## 修复卫生
- **修复引入的新数学是未被审计的数学**：每一波修复之后，都要对恰好这些被修的位置跟进一波验证，然后才能宣布任何东西收口。
- **在工作流综合中，按 INDEX 把发现与判定配对**（要求裁判者按发现的顺序返回判定），绝不要按位置字符串配对——裁判者会改写位置，静默丢失随之而来。动手之前，先把综合出的摘要与日志核对一遍。

## 走不通的路也是结果
若某个组件在所述假设下无法修好，那是一条*发现*，不是审计的失败：报告确切还差什么（精确缺失的假设或断掉的那一步）以及诚实的选项（削弱论断、补上假设、收窄范围）。不要去搜一个更有利的读法，也不要让某个代理把一处定理强度的缺口糊成 "routine"。

## 编排
- 在一条消息里用并行的 `Agent` 调用扇出（每个组件一个查找者），然后每个组件配一名裁判者裁定该组件的发现，再做综合；见 [`orchestrator-protocol.md`](../../rules/orchestrator-protocol.md)。在 Workflow 工具可用的地方（例如 `ultracode` 会话），`pipeline(components, finder, judge)` 是一个可选加速器，它在某个查找者一返回就裁定该组件的发现（无栅栏）；它永远不是必需项。返回被确认的清单；之后由你自己动手修。
- **模型分工：** 查找者 = 强的*执行/分析*模型（找并攻击）；裁判者 = 强的*裁定*模型。按 [`model-routing.md`](../../rules/model-routing.md) 里的本地约定对齐（此处：两个角色都跑在 Opus 层，且裁判者先加努力度、再动层级；Fable 层是逐会话的选择，绝不是机群默认）。裁判者保持每个组件一名（一次性裁定该组件的全部发现），以节省裁定预算。
- 把查找者的 `effort` 设高；给每一个确切的标签/位置去读，以及它具体的攻击清单。
- **咬住不放。** 不要返回 "best effort"，也不要返回一份"为什么难"的清单。返回被确认的缺陷（修好之后，再返回一次干净的复审计）——或者把剩下最强的那个缺口精确地讲清楚。

## 提示词骨架
查找者：*"你是一名敌意审稿人，正在审计一个组件。读 {locations} 处实际的文本。攻击：{failure modes}。只返回具体的发现（位置 + 缺陷 + 失败用例）；不要 'looks fine'/'routine'/含糊。把困难挪到别处的修法不是修法。若判定干净，列出你跑过的具体攻击以及每一次为何闭合。"*

裁判者：*"一名对抗式审稿人就组件 X 返回了这些发现。对每一条，打开所引位置，对照文本实际说了什么及其证明做核实，标记 CONFIRMED/REFUTED/DOWNGRADED。对产物与发现两者都保持怀疑。"*

## 共享信条只写在一处

这次审计依赖的三件事**不**在这里重述，因为它们就是其他每个验证面都在用的同一套规则，写第三份会漂移：

- **播种故障校准**——没抓住过植入缺陷的检查，什么也不背书。
  → [`/vaccinate`](../vaccinate/SKILL.md)，以及 [`verification-ladder.md`](../../references/verification-ladder.md) rung 0。
- **独立性与相关误差**——模型之间的一致不是确证；它们以同样的方式失败。
  → [`verification-ladder.md`](../../references/verification-ladder.md) rung 3。
- **五个可信度问题**——对其中一个的证据，永远不能清掉另一个。
  → [`external-oracle-process.md`](../../references/external-oracle-process.md) §6。
