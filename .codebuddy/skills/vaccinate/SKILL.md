# Vaccinate — 给评分者评分

曾有人把二十个 bug 植入一份可运行的代码库，再请审查代理检查。代理报告一切正常，**Recall: 0/20。**

疫苗用少量受控错误帮助系统建立防御。本技能采用同样的思路。

**它执行一条规则：未经资格认定的检查不是弱证据，而是根本不能算证据。**

## 何时运行它

- 在把审稿人模拟、可复现性门禁或审查代理用于投稿、发布、存档等重要决定之前。
- 修改检查器之后。修改过的门禁必须重新测量，否则视为未经资格认定。
- 对守护关键结论的门禁定期运行。产物变化后，检查器的检出能力可能下降。

## 流程

### 1. 说清失败是什么

明确该检查本应抓住的缺陷**类别**。「能抓住问题」不是类别；「能检出正文系数与表格不一致」才是。

### 2. 固定设计并构建中立播种集 + 干净对照

**运行前**写定播种缺陷数 **N**、干净对照份数 **C（至少 1）**、召回率阈值和误报对照率阈值；看到结果后不得调整对照数量或阈值。

只在**仓库外的中立副本或完整夹具**上操作，绝不直接修改正在使用的 README 或其他活产物。完整夹具必须包含检查器运行所需的全部输入，不能悄悄回读仓库。生成：

- **N 份播种变体**，每份包含一处取自 `references/defect-library.md` 的缺陷。
- **C 份干净对照**，即未修改的中立副本或夹具。

对照不可缺少。没有对照，就只能测量召回率，不能测量误报。台账的 **Artifact** 项必须记录中立副本/夹具的位置与来源哈希，并用 **Isolation** 项记录隔离方式；不能只记录活仓库中的文件路径。

**逐一核实每颗种子确实违反了某项要求。** 如果产物本来就允许该内容，它就不构成缺陷；检查器如实报告 "pass" 也不表示门禁失效。这是资格认定误报检查器问题的最常见原因。

### 3. 盲跑检查器

在**独立上下文**中分别对每份变体运行检查或代理，每次只处理一份。检查器不得知道自己拿到哪份变体、共有几处缺陷，也不得知道正在进行资格认定。测试 AI 审查者时，另起一次独立上下文的 `Agent` 调用；不要使用会话分叉，因为它会继承播种答案。必须通过目录权限或沙箱保证 **Agent 无仓库访问权**，只向它提供仓库外的中立副本或完整夹具；仅在提示词中要求不要访问不算隔离。无法保证隔离时记为 **BLOCKED**。

### 4. 计分

| 指标 | 定义 |
|---|---|
| **召回率** | 正确识别的播种缺陷数 / 播种的缺陷总数 N |
| **误报对照率（FPR）** | 逐份判断**每份干净对照是否产生至少一条事实错误发现**；产生此类发现的对照份数 / 运行前固定的干净对照总份数 C |
| **定位** | 它是否指出正确位置，而不只是表达疑虑？ |
| **基线差值** | 一个**更简单的替代方案**（一次 grep、一次 diff、一行断言）的召回率 |

干净对照中的发现只有**事实错误**时才计为误报，仅仅不受欢迎不算。某份对照零发现就记为该份 **0 次误报**；全部对照都零发现时，FPR 为 **0/C = 0**，分母始终是运行前固定的 C。C=0 违反设计，不能计分。被要求寻找缺陷的审查者即使面对可靠工作，也可能报告一些问题；只有事实错误发现才使该份对照计入误报分子。

**基线必须保留。** 如果一个五代理小组的表现不如 `grep -n`，它就没有证明自身值得额外成本。

### 5. 写下台账行

追加到 `quality_reports/qualification/LEDGER.md`：

```
| date | target | artifact | isolation | defect classes | N | C | recall | FPR | thresholds | baseline | verdict |
```

`artifact` 记录中立副本/完整夹具及其来源哈希，`isolation` 记录仓库外位置、完整夹具边界和 Agent 无仓库访问权的实现方式。判定为：**PASS**（达到运行前固定的召回率与误报对照率阈值）、**FAIL**（未达到任一固定阈值）或 **BLOCKED**（无法运行或无法保证隔离，需说明原因，不得记为 PASS）。

### 6. 按结果行动

- **FAIL** → 该检查不能支持其声明的能力。修复检查或停止引用它，**不要**通过削弱种子让它通过。
- **PASS** → 记录阈值。在某一难度上 PASS，不代表在另一难度上也 PASS。
- 无论结果如何，没有台账行的检查器都属于**未经资格认定**，其通过结果没有意义。

## 完整示例

```
/vaccinate check-model-versions.sh
```

1. 失败类别：「把已被取代的模型当作当前模型展示」。运行前固定 N=1、C=1、Recall 阈值为 1/1、FPR 阈值为 0/1。
2. 在仓库外建立完整夹具，复制 `README.md` 及检查所需输入；绝不修改活 README。种子：只向夹具中的副本追加 `The newest model is Opus 4.8 and it is the default.`。对照：同一夹具中未修改的副本。Artifact 记录来源哈希，Isolation 记录仓库外路径与访问边界。
3. 让 `bash scripts/check-model-versions.sh` 只检查夹具目标并记录退出码；若使用 Agent，沙箱必须禁止它访问仓库。
4. 计分：播种版退出码为 **1**，表示检出；干净对照退出码为 **0** 且零发现，该对照记 **0 次误报**。Recall 1/1，FPR **0/1 = 0**。基线 `grep -c "Opus 4.8" <fixture>/README.md` 也能检出，因此这个门禁的价值在于允许标记逻辑，而不只是发现字符串。
5. 达到运行前固定的阈值，台账记录 `PASS`。
6. 重跑中立夹具中的干净对照，确认结果可复现；活仓库从未被修改，无需复原。

## 反模式

- **在本来就允许该内容的产物中播种**：没有测到目标缺陷，却可能误以为门禁失效。
- **告诉审查者这是一次测试**：它可能比实际运行时更努力。
- **把任何发现都算作命中**：位置错误的发现不算检出。
- **只播一颗种子、只跑一次**：单次试验无法区分真实检出和运气。成本允许时，每个类别至少重复 2 次。
- **削弱种子直到通过**：这是在让测试迁就检查器。
- **跳过干净对照**：这是最常见的遗漏，也会隐藏误报代价。

# 信条：资格认定意味着什么

## 不要假定机器更多就更好

不能默认第二个模型、更多代理或更长辩论会带来更好的验证。繁复流程要获得额外权重，必须先证明它在同一批预先指定的播种失败和合法用例上胜过更简单的检查，并同时报告检出和误报。无法胜过基线的复杂设计只会增加成本，不能提供保障。

## 把 AI 判定当预测，而不是事实

模型大规模评分、分诊或审查时：

- 保留一个**抽样集交合格人工复核**，并记录抽样方式。抽样要覆盖困难子群，不能只选容易的中间段。
- 将用于拟合或提示词调优的用例与评估用例**分开**。
- 报告 AI 判断与专家判断的分歧。
- 记住，校准良好的*平均*分不能为任何单个判定背书。
- **模型之间的一致不是独立证据**，因为它们共享失效模式，并可能以可观比例收敛到同一个错误答案。

模型、提示词、评分细则或目标人群发生任何实质变化后，都要重新获取人工标注并重新校准。

## 实质改动后重新进行资格认定

针对旧接口、旧 schema 或旧量纲认定的检查，可能已经悄悄失去测试对象。被测对象或检查自身发生实质变化后，重新运行播种缺陷证明。

## 把合格检查与科学判断区分开

- **合格检查**有可靠的参考答案：键唯一、单位可换算、表格可重新生成、估计量可以还原一个解析特例、播种故障能触发失败。这些检查可以自动化并反复运行。
- **科学判断**包括字段是否度量了目标构念、识别假设是否可信、结果是否适合使用因果措辞。这些无法自动化，**再多合格检查也不能替代科学判断。**

## 确认检查真的跑过

缺失、被替换或被降级的检查属于**缺失证据**，不是通过。要核实本次运行确实发生，可检查日志、退出状态和产物时间戳，不能靠假设；确认它运行于**当前**对象而非缓存副本；确认没有内容被跳过、过滤或吞进默认值；容差必须在比较**之前**确定。*比较失败后才放宽容差，会让证据失去作用。* 如果必须放宽，应记录为带理由的已批准偏离。
