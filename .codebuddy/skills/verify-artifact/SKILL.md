# 在产物离开之前核验它

一次审读的好坏，取决于被审的那个东西。如果产物是损坏的、被截断的、过期的，或悄悄重排过编号的，一位称职的审读者会带回关于**你工作里并不存在的**缺陷的自信发现——而你会花掉一整个周期去追它们。预防很便宜，漏掉很贵。

**规则：绝不发送一个你没有与它的源做过 diff 的派生产物。**

## 1. 在一次 shell 调用里从源重建

绝不发昨天那次构建。重建，然后在*同一条*命令里拷到发送位置，这样中途不可能有东西变掉。

云同步文件夹（Dropbox/iCloud/OneDrive）会**给文件脱水**：一个 PDF 可能在构建与读取之间变成 0 字节或一份不完整的副本。症状：`Syntax Error: Couldn't find trailer dictionary`、一个本该 700 KB 的文件只有 70 KB。构建工具的「已是最新」提示*不是*文件完整的证据——工具检查的是时间戳，不是内容。永远先落到一个本地（非同步）目录，在那里核验。

## 2. 完整性检查（机械、快、不可协商）

- **大小与结构**：字节大小在预期区间内；页数／记录数／行数与预期相符。
- **能解析**：用一个真正的读取器打开它（`pdfinfo`、`pdftotext`、一个 JSON/CSV 解析器、`unzip -t`）。文件存在不等于文件能用。
- **抽样看内容**：首页与末页／首条与末条记录确实含有你预期的东西——截断会显现在末尾。
- **未解析的标记**：对文档，数 `??`、`[cite]`、`TODO`、`XXX`、残留的 `\ref{`、「Chapter ??」；对代码／数据，数 NaN、空单元、占位值。

## 3. 把派生产物与它的源做 diff

这是人们会跳过、也是唯一有回报的一步。若产物是经变换、摘录、压缩或取子集得来的，那**就枚举可能丢掉的东西**并检查：

- **标签／锚点／ID**：源与产物中的标识符集合。任何在源里定义了、在产物里*被引用却缺失*的东西，就是一处断裂。
- **编号**：删掉一个带编号的对象会悄悄给它之后的一切重编号，于是一条原本「Lemma 10」的引用变成「Lemma 6」——每个下游引用现在都指向一个看起来合理却错误的地方。检查编号的稳定性，不只是存在性。
- **计数**：章节、表格、图、行、函数、端点——改前 vs 改后。
- **嵌套内容**：摘录一个块，可能连带删掉嵌在它里面的*陈述*，而不只是你打算剪掉的散文。

若你剪掉了任何东西，就在产物内部留一条可见的说明，好让审读者不会把一处省略读成一个缺口。

## 4. 让收件人证明他们拿到了什么

请审读者（人或模型）**在他们回复的开头写明**他们正在审的确切文件名、页数／记录数，以及版本。这能抓住过期的缓存、错误的附件，以及悄悄回退到更早的上传——这些失败在别处不可见，直到发现变得莫名其妙。

每轮用不重复的文件名（`report_r6.pdf`，而不是 `report.pdf`）。重复的同名会招呼收件人的系统提供一份缓存的旧副本。

## 5. 发现看起来奇怪时，先怀疑产物

在依据一次审读行动之前，先问：这条发现会不会是我发出去的东西的产物？信号：抱怨引用缺失／未定义、「章节似乎被截断」、「证明在论证中途断掉」、编号与你手上的副本对不上，或反对你确知存在的文字。**先重新核验产物，再重新核验工作。**为产物引发的发现去施加「修复」，会实际损坏正确的材料。

## 最小检查清单

1. 从源重建；在同一条 shell 命令里落到本地目录。
2. 核验它能解析；检查大小、计数、首末内容。
3. 数未解析的标记——期望是零。
4. 与源 diff 标识符／编号／计数；把任何刻意的省略记在产物本身里。
5. 本轮用一个不重复的文件名。
6. 要求收件人复述文件名 + 计数。
