# 在产物离开之前核验它

审读质量首先取决于实际交付的文件。如果产物损坏、被截断、已经过期或编号被悄悄重排，称职的审读者也可能自信地报告一些**你的工作里并不存在**的缺陷，而你会花整个周期追查。提前核验成本很低，遗漏的代价却很高。

**规则：没有与源文件做过 diff 的派生产物，绝不发送。**

## 1. 在一次 shell 调用里从源重建

不要发送昨天构建的文件。先重建，并在同一条命令中复制到发送位置，避免文件在两步之间发生变化。

云同步文件夹（Dropbox/iCloud/OneDrive）可能让文件暂时失去本地内容：PDF 可能在构建与读取之间变成 0 字节或不完整副本。典型症状包括 `Syntax Error: Couldn't find trailer dictionary`，或本该 700 KB 的文件只有 70 KB。构建工具提示「已是最新」也不能证明文件完整，因为它检查的是时间戳而非内容。始终先输出到本地非同步目录，并在那里核验。

## 2. 完整性检查（机械、快、不可协商）

- **大小与结构**：字节大小位于预期区间，页数、记录数或行数符合预期。
- **能够解析**：用真正的读取器打开，例如 `pdfinfo`、`pdftotext`、JSON/CSV 解析器或 `unzip -t`。文件存在不等于文件可用。
- **抽样检查内容**：首页与末页、首条与末条记录确实包含预期内容，末尾尤其容易暴露截断。
- **未解析标记**：检查编译日志中的 `undefined references`、`Reference ... undefined` 和 `Citation ... undefined`，并检查渲染输出文本中的 `??` 与「Chapter ??」；另查 `[cite]`、`TODO`、`XXX`，代码或数据中查 NaN、空单元和占位值。正常 LaTeX 源里的 `\ref{...}` 是有效交叉引用语法，**不得把 `\ref{` 本身扫描为错误**。

## 3. 把派生产物与它的源做 diff

这是关键一步，也最容易被跳过。如果产物经过变换、摘录、压缩或取子集，先枚举可能丢失的内容，再逐项检查：

- **标签、锚点和 ID**：比较源与产物中的标识符集合。源中已定义、产物中仍被引用却缺失的内容，就是一处断裂。
- **编号**：删除带编号对象会悄悄重排后续编号。原本指向「Lemma 10」的引用可能变成「Lemma 6」，使所有下游引用指向看似合理但实际错误的位置。因此不仅要检查编号是否存在，还要检查是否稳定。
- **计数**：比较改动前后的章节、表格、图、行、函数和端点数量。
- **嵌套内容**：摘录一个块时，可能连同删除其中嵌套的陈述，而不只是打算删去的散文。

如果删去了任何内容，应在产物内留下可见说明，避免审读者把有意省略误读为内容缺口。

## 4. 让收件人证明他们拿到了什么

请审读者（人或模型）在回复开头写明正在审查的确切文件名、页数或记录数，以及版本。这能发现过期缓存、错误附件和悄悄回退到早期上传版本等问题；否则，这些故障往往要到发现变得难以理解时才会暴露。

每次交付使用不重复的**随机中立标识**作为文件名，例如 `artifact_7f3a9c2e.pdf`，不要反复使用 `report.pdf`，也不要用 `report_r6.pdf` 这类在文件名中编码轮次、进度或评价状态的名称。随机标识应不可猜测且不含内容含义，以避免缓存旧副本和让文件名影响审读者。

把随机标识与原始文件名、来源路径、内容哈希、构建时间和交付对象之间的映射另存到交付方保留的映射文件；映射不依赖交付文件名自身，也不随公开交付件发送。收件人复述随机文件名后，用它回查映射，确认双方指向同一版本。

## 5. 发现看起来奇怪时，先怀疑产物

根据审读结果采取行动前，先问：这条发现会不会来自我发出的文件？常见信号包括抱怨引用缺失或未定义、「章节似乎被截断」、「证明在论证中途断掉」、编号与你手头副本不一致，或反对你确认存在的文字。

**先重新核验产物，再重新核验工作。** 为产物问题实施所谓「修复」，反而可能损坏正确材料。

## 最小检查清单

1. 从源重建，并在同一条 shell 命令中输出到本地目录。
2. 核验文件能够解析，检查大小、计数和首末内容。
3. 检查编译日志的 undefined references/citations 与渲染输出的 `??`，预期数量为零；不要扫描正常 `\ref{` 充作错误。
4. 与源文件 diff 标识符、编号和计数，并在产物中记录所有有意省略。
5. 使用不编码轮次的随机中立文件名，并把标识与版本映射另存到交付方保留的文件。
6. 要求收件人复述随机文件名和计数，再用映射核对版本。
